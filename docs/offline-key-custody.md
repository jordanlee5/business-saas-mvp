## 用户需要做的事

1. 准备一只可信U盘，插入电脑，记下“此电脑”里的盘符，例如 F盘。无需格式化，不要删除原文件。告诉助手盘符即可，不发送任何密钥或密码。
2. 准备一个独立、较长的密码，建议20位以上；导出工具只在本机终端隐藏输入并要求重复确认，不从聊天、命令参数或环境变量读取密码。密码放在另外的密码管理器或妥善保管的纸上，不与U盘放在一起。
3. 按助手给出的本机命令导出到U盘上的**新目录**。工具写出带密码保护的密钥副本、公钥及识别信息，重新读取并验证后才显示成功；不改原密钥、不停业务服务。
4. 安全弹出U盘，再插入，执行只读验证并再次在本机输入密码。确认通过后安全弹出，存放到与电脑分开的安全位置。
5. 不删除电脑内原私钥，也不要把U盘中的密钥文件发到聊天、微信、网盘公开链接或GitHub。建议准备第二份独立保管副本，但本轮没有购买任何设备或服务。

本轮未检测到可移动U盘，**未导出实际私钥，离线保管仍待上述操作完成**。虚拟密钥演练不能代替实际U盘的重新插入读回验收。

## 已准备的工具与恢复方式

`tools.staging_key_custody` 使用 cryptography 的标准 PKCS8 密码加密格式。只允许交互式隐藏输入密码；拒绝输入回显降级、弱于16字节的密码、新副本与源密钥目录重叠、链接路径和既有目标。导出后读回副本，核对公钥与随机加解密挑战，原私钥保持。

在 Linux/WSL 中操作；下面占位符需替换为经核实的本机路径。Windows U盘可能需要先挂载到WSL，未挂载时停止，不写入同名本地替代目录。只在确认挂载的离线介质中导出，不将普通文件夹当成已完成离线存储。

```sh
python3 -m tools.staging_key_custody export <原私钥文件> --destination <U盘挂载路径/新目录>
python3 -m tools.staging_key_custody verify <U盘上的副本目录> --public-key <原公钥文件>
```

灾难恢复时先验证副本，再把私钥恢复到全新的Linux私密目录。不能把未加密私钥恢复到U盘目录，目标必须能执行仅所有者可访问的权限规则。之后用原 `staging_backup_crypto decrypt` 解密备份，再按隔离恢复流程操作。密码丢失不能靠现有工具绕过。

```sh
python3 -m tools.staging_key_custody recover <U盘上的副本目录> --destination <新的Linux私密目录> --public-key <已保存的对应公钥文件>
```

参考 [cryptography密钥序列化文档](https://cryptography.io/en/50.0.2/hazmat/primitives/asymmetric/serialization/)。

## 对话作业结束后能否关机

可以关机，但先等当前本机拉取、密钥导出或其他作业结束。关闭对话或电脑不会修改服务器上的定时任务。

| 项目 | 管理电脑关机后的行为 |
| --- | --- |
| 云端凌晨加密备份 | 在服务器运行，不需要本机私钥，照常执行；原备份过程仍有短暂停应用窗口 |
| 云端巡检和企业微信通知 | 服务器正常联网时继续工作；服务器整机失联仍缺外部监测 |
| Windows每小时异机拉取 | 停止；睡眠、休眠、注销期间也不运行。仅锁屏可继续，但仍需防止自动睡眠 |
| 下次开机 | 联网并登录安装任务的Windows账户后触发补拉，补最新有效点，不保证补齐全部历史点 |
| 长时间关机 | 本机副本停留在旧版本；来源或回执超过36小时可触发异机过期告警。服务器7个已确认点与本机14点规则保持，未确认点保留，并非硬容量上限 |

若希望首个凌晨加密备份当晚就自动拉到本机，应保持开机、联网、已登录且不睡眠，等凌晨备份与随后小时拉取成功后再关机。若今晚关机，次日登录后再核对云端备份和补拉结果，不需要为验证手动重新跑停机备份。
