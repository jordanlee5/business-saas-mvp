# UI反馈第2小轮：订单直达与交易页简化

基线 `3c7ef25760767e0eaf9ebafd847e6eb62ddfbc6d`。2026-10-29用户确认购物车缩略图位置与点击进入详情满意，允许继续下一项。本轮保持现有配色、地址录入及账务规则，仅处理已讨论的订单链路与供应商卡片。

## 客户可见变化

- 确认兑换后，校验成功响应并清除本次待确认标记，直接替换当前页面进入本单详情。无需经过提交结果页、订单列表再点击详情。详情首部显示订单提交成功、当前状态、商品和积分合计；同页保留收货地址、已有承运人/运单号及取消入口。
- “查看全部订单”回到订单列表，“继续逛好物”返回商城。个人中心的订单入口仍展示全部订单。详情页面暂时隐藏后返回，继续读取该订单，避免自动退回列表。
- 移出确认页和订单详情中的供应商名称、分供应商商品大卡片。页面仅保留“配送及售后由本公司统一安排”和可展开的“配送与隐私说明”，说明必要收货信息用途并展示已有公司客服；完整隐私指引入口仍在个人中心。
- 确认页用“相应积分将暂时不可用于其他兑换；取消后积分退回”说明效果，取消确认用“本单使用的积分将退回”。没有修改实际积分预占/消费/退回时点。积分流水页留待下一轮。

## 失败与隐私边界

跳转只携带订单公开编号和两个状态标记，不携带姓名、电话、地址或令牌。详情仍通过会员私有接口读取，未知/其他会员订单由原接口拒绝。

提交结果不确定时保留原请求号，先查询、重试或核对原订单；没有因为精简跳转而创建新编号。成功后跳转失败显示可重试的“查看订单详情”，禁止再提交一次。详情读取失败或取消响应丢失时仍保留目标订单编号，“刷新本单”继续核对原订单，不误展示空订单列表。页面隐藏时清除详情与展开说明，晚到响应不能恢复隐藏页面的个人信息。

本轮移出可见供应商卡片，原API字段、受托资料摘要检查与订单履约安排历史JSON兼容保留，未删后台记录。历史JSON是内部履约安排记录，不能据此声称用户逐项看过其中所有供应商字段，更不等于用户对独立共享作了单独同意。个人信息使用说明与正式平台隐私指引仍需保持一致，隐私审核通过标志继续为空，未提交审核。

当前仍仅展示系统已有运单资料；未接入供应商自动回传或物流轨迹API。真实库仍0013，新版服务真实联调前0014升级仍须另行确认。本轮没有迁移，也不执行真实清理。

## 验收方式

原离线验收项目点击编译后，模拟登录并放商品入购物车。确认地址和商品后提交，应直接看到订单详情。检查供应商大卡片已移出，配送说明可展开/收起；取消后可刷新本单，也可查看全部订单或继续逛。

控制台切到“提交成功但响应丢失”，再次兑换后先显示待确认状态；点查询提交结果，应进入已经创建的同一订单详情。此处是虚拟数据，不代表真实微信平台或供应商联调验收。

客户端回归新增6组覆盖跳转失败、未知提交查询后直达、带编号进入和隐藏返回、404后本单重试、取消结果不确定后刷新、无效链接安全返回列表。既有重复点击、会员隔离和晚到响应检查保留。生成演示项目的页面脚本串联也验证订单直达和详情刷新；原生渲染仍待用户复验。
