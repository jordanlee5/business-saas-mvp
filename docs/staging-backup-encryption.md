## 加密与恢复规则

新格式为 2：数据库导出、业务文件、会话材料及原始清单打包后使用 AES-256-GCM 加密；每个恢复点独立随机数据密钥和 nonce，以 RSA-3072/OAEP-SHA256 公钥封装数据密钥。项目、备份时间、镜像 ID 与封装参数作为认证附加数据。服务器只持公钥，私钥不上传、不进入备份树或 Git。

通过 `STAGING_BACKUP_PUBLIC_KEY` 显式启用。公钥不可用时在停应用前拒绝；正常备份恢复应用并确认健康后才加密。加密失败保存固定错误码，保留之前的成功指针，进入现有失败巡检。仅在密文完整性检查成功后删除本轮新建明文暂存目录；异常暂存、旧恢复点保留，需人工检查。删除不代表物理安全擦除；文件系统快照、交换空间与底层磁盘保护另行管理。

加解密使用现有 Python cryptography 组件，无新服务费用；未更新系统依赖或运行应用。流式处理，上限 20 GiB；加密/解密均需要额外临时磁盘空间。密文清单保留项目、时间、镜像信息；不隐藏备份大小。公开摘要只用于传输损坏检查，不能代替持私钥后的 GCM 认证；公钥持有人可以制作新备份，不将其视为来源数字签名。

恢复必须先在 Linux/WSL 仓库外新目录完成解密。错误密钥、损坏密文、被改动元数据均拒绝；全部 GCM 认证通过后才解析归档，验证普通文件、路径及原始文件清单，最后发布解密结果。既有目录不覆盖。再调用原恢复入口，仍需全新独立项目、精确镜像及另行保管的部署凭据。直接向恢复入口传密文会拒绝。

```sh
python3 -m tools.staging_backup_crypto keygen <新的独立私密密钥目录>
python3 -m tools.staging_backup_crypto encrypt <新的密文目录> --source <已核验的备份目录> --key <公钥文件>
python3 -m tools.staging_backup_crypto decrypt <新的私密解密目录> --source <密文目录> --key <独立私钥文件>
python3 -m tools.staging_pg_backup restore <已解密目录> --project <全新saas-pg-test项目>
```

## 当前密钥保管边界

实际私钥在管理电脑 WSL 的独立 root 私密目录，目录 700、文件 600；与 Windows 自动副本目录分离，服务器只有公钥。实际路径仅留本机交接记录。工具拒绝权限过宽的私钥，Windows 密文拉取不需要私钥或加密依赖。

**尚无独立离线介质上的私钥副本。** 电脑整体损坏仍可能同时失去副本与密钥，不能将当前目录分离称为完整异地密钥容灾。后续应由保管人在可信离线介质或独立密码库保存私钥并验证读取，不能把私钥发到聊天、GitHub、备份服务器或副本目录。保留历史密钥直至所有对应恢复点均到期；更换公钥只影响新备份，不删除旧私钥。
