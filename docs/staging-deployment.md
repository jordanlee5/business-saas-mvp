## 现在需要准备什么

| 项目 | 当前情况 | 谁来完成 |
| --- | --- | --- |
| 云账号与企业实名 | 是否已有可登录账号待确认 | 用户登录并完成平台要求的本人核验 |
| 云服务器 | 尚未购买 | 用户核对订单后购买，开发方配置部署 |
| 公司域名 | 尚未注册，名称待选 | 用户确认名称并以公司资料实名注册 |
| ICP 备案与域名接入 | 尚未办理 | 用户按云平台流程提交资料及核验，开发方配合技术信息 |
| HTTPS 证书 | 尚未申请 | 域名和网络就绪后，由配置好的 Caddy 自动申请、续期 |
| 微信后台服务器域名 | 等待测试域名 | 用户在小程序后台完成管理员确认，开发方填写对应工程地址 |
| 服务器登录入口 | 等待创建服务器 | 提供公网 IP、登录用户名和可用的登录方式，密钥保管在本机 |

服务器相当于一直开着的电脑，域名是访问它的网址，HTTPS 是浏览器和小程序使用的加密连接。服务器买好后可以先在受限环境安装程序。公网域名联调需要完成相应备案、解析和证书配置。

## 建议选购方案及费用

最新建议是腾讯云 CVM 标准云服务器，上海、Ubuntu 24.04 LTS x86_64、4 核 8GB、80～100GB SSD，10Mbps 公网带宽作为测试起点，先购买 3 个月。它用于虚拟数据联调，不能据本机压测承诺正式容量。8 CPU 双进程对集中兑换有帮助，但未消除混合负载中的数秒等待，也没有 16GB 内存收益的验证。后台共享会话和 PostgreSQL 已准备，生产默认仍为单进程，目标服务器验证后再配置进程数。

服务器、磁盘和带宽的月均总价要控制在用户约 1,000 元预算内，并为域名和备份留余量。CVM 的具体选配报价尚未取得，购买和续费价格以登录后的订单为准。此前轻量 245 元/月的公开套餐只是备选比较，不能套用为 CVM 价格；实际选配和购买入口见[采购指南](test-server-purchase.md)。

域名选择公司可长期使用的普通 .com 或 .cn，先看首年价格和续费价格。测试环境使用它下面的子域名，例如 `mall-test.你的域名`，子域名通过解析记录创建。HTTPS 使用自动证书，域名解析正确、80/443 可达、证书目录持久保存后，Caddy 可自动签发和续期。[自动 HTTPS 条件](https://caddyserver.com/docs/automatic-https)

腾讯云文档要求，用轻量服务器办理备案须购买中国境内实例，购买时长至少 3 个月，备案期间剩余有效期至少 1 个月。购机时一并确认实例可用于备案。[备案云资源要求](https://cloud.tencent.cn/document/product/243/18908)

## 你按这个顺序配合

1. 登录或注册腾讯云，按公司主体完成实名。告诉开发方是否已能进入控制台，以及你已有的云平台账号偏好。
2. 给出 2～3 个域名候选名称，或公司希望使用的英文简称。确认价格、续费和实名主体后，由你支付注册。
3. 进入[腾讯云 CVM 自定义购买](https://buy.cloud.tencent.com/cvm?tab=custom)，按最新采购指南选择配置并核对新购、续费及升级价格。报价合适后由你付款；若超出预算，先保存选配结果重新比较，不直接付款。
4. 按腾讯云备案向导完成企业资料、负责人资料和本人核验。证件和验证码直接交平台。域名实名信息与备案主体按平台要求核对。
5. 服务器开通后提供公网 IP、操作系统、登录用户名和登录方式。SSH 私钥保存在本机。需要扫码或验证码时由你操作，开发方负责安装和配置。
6. 备案及接入准备就绪后，在域名解析中增加一条 A 记录。主机记录填 `mall-test`，记录值填服务器公网 IPv4。仅启用已确认可达的 IPv6 记录。开发方核对解析、80/443 放行、证书和页面。
7. 在微信公众平台中把同一个 HTTPS 地址登记到 request 和 downloadFile 合法域名，完成管理员确认。开发方更新小程序工程地址、编译，再安排手机看图验收。[微信域名配置说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)

第一轮公网验收包括后台登录、上传或替换商品图、手机查看列表/详情/购物车，以及服务器重启后复看。会员真实登录与权益兑换另需新账号的隐私状态、服务器秘密配置和正式业务资料就绪。当前部署包用于后台及公开商品链路，微信 AppSecret 与隐私批准值仍由后续接入步骤配置。

## 历史 SQLite 部署步骤（当前请使用 PostgreSQL 包）

以下保留此前 SQLite 包的开发方操作记录。**本次购机后的部署请执行 [PostgreSQL 部署及恢复说明](postgres-staging.md)，不照搬下面 SQLite 初始化命令。** 服务器应已按照官方步骤安装 Docker Engine、Compose 插件及 Git，并具备外部镜像和 Python 依赖下载能力。[Ubuntu 安装说明](https://docs.docker.com/engine/install/ubuntu/)

1. 获取经过验证的 Git 提交，进入仓库的 `deploy/staging` 目录。复制 `.env.example` 为 `.env`，只填写已经确定的测试子域名，格式为裸域名，例如 `mall-test.company.cn`。保留购买与解析核对记录。
2. 云防火墙放行 TCP 80/443。SSH 22 仅对已确认的管理来源放行。应用 8000 和数据库端口保持内部可用。Compose 的应用服务没有映射宿主机端口，只有网关对外服务。
3. 核对配置并构建镜像。

```sh
docker compose config --quiet
docker compose build app
```

4. 在全新专用数据卷初始化空测试库。初始化采用排他创建，遇到已有数据库会停止。失败时检查卷内状态后处理，已有数据库升级须另行备份和评审。

```sh
docker compose run --rm --no-deps app python -m tools.staging_server initialize
docker compose run --rm --no-deps app python -m app.init_admin
docker compose run --rm --no-deps app python -m tools.staging_server check
```

管理员用户名为 admin，初始密码由操作者隐藏输入两次，至少 12 位。已有 admin 账号保持原有凭据。首次登录要求修改密码。启动检查要求存在有效超级管理员，且拒绝旧的固定默认密码。

5. 解析和公网入口就绪后检查网关配置并启动。

```sh
docker compose run --rm --no-deps gateway caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
docker compose up -d --wait
docker compose ps
```

检查测试域名的 `/health`、`/login` 和商品图。检查证书域名匹配和完整证书链。真实域名验证不能由本机内部证书代替。

6. 导入或手工创建虚拟商品和库存。核对后台换图、小程序取图、原件直链拒绝和跨账号拒绝，记录浏览器和手机结果。重建应用容器后复验。

```sh
docker compose up -d --force-recreate --wait
```

7. 在测试环境停止应用后，备份同一持久卷里的 `staging.db`、`uploads` 和 `session.key`。通过 `docker compose cp app:/data/. <新的私有备份目录>` 取出，校验文件摘要后再启动应用。备份放在权限受限目录，另留服务器之外的副本。恢复时使用新卷，恢复内容归属 10001:10001，以相同代码版本启动、验证权限与图片，并记录恢复时间。证书卷也应纳入运维备份。后续接入的微信秘密配置另行受限备份。

原 SQLite 测试入口仍固定单进程；从 `0017_backoffice_sessions` 起后台使用数据库共享会话，普通重启保留有效登录。上面的 SQLite 手工恢复流程不会自动撤销历史登录：恢复到新卷后、应用启动前，开发方必须在该隔离恢复库清空 `backoffice_sessions` 表，不能在源库执行。优先使用已经自动完成该步骤的 PostgreSQL 恢复工具。多进程测试见[共享会话说明](shared-browser-sessions.md)。网关只转发 HTTP 请求，不直接映射上传文件。应用只在专用容器网络信任转发头，以正确生成 HTTPS 安全 Cookie；该网络只连接本套应用和网关。应用容器使用非 root 账号。

部署前还需核对实际服务器磁盘、可用内存、镜像下载和备份恢复。每次提交的构建记录应保留镜像摘要。目标服务器的证书签发、续期、故障恢复和手机联调需在服务器开通后取得真实证据。本轮本机验证详见仓库 validation 下的对应记录。

本轮 Linux 应用镜像已实际构建并运行。官方网关容器分发站连接超时，本机演练改用经官方 SHA-512 清单校验的 Caddy 2.11.8 程序封装临时网关，使用本机 CA 证书。HTTPS 登录、首次改密要求、私有附件拦截、重建容器和新卷恢复均已验证。正式配置仍使用官方 Caddy 容器镜像，其拉取与运行需在目标服务器复验。[本轮验证记录](validation/staging-prepare-20261105.json)
