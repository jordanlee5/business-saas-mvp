# M6-16-1 订单状态流转业务接管

订单表当前只允许 `CREATED`、`CANCELLED`、`FULFILLING`、`SHIPPED`、`COMPLETED`、`REFUNDED`。预占在 `CREATED` 下由积分与库存流水表示；完成后的四账对账为只读核验，供应商结算由独立批次及明细记录。这些业务事实不改变订单状态。

| 动作 | 首次允许的状态 | 首次目标 | 同一目标下重放 |
| --- | --- | --- | --- |
| 取消 | `CREATED` | `CANCELLED` | 既有会员/管理员取消规则及释放证据完整时 |
| 确认履约 | `CREATED` | `FULFILLING` | 履约审计、积分消费和库存出库完整时 |
| 发货 | `FULFILLING` | `SHIPPED` | 物流信息相同且发货证据完整时 |
| 确认完成 | `SHIPPED` | `COMPLETED` | 完成审计及此前证据完整时 |
| 整单退款 | `COMPLETED` | `REFUNDED` | 原因相同且退款、积分及库存证据完整时 |

其他状态与动作组合拒绝。`CANCELLED` 和 `REFUNDED` 只允许自身对应动作经过原有证据校验后的幂等重放。状态机纯函数只决定允许、目标和重放候选；原子领域服务继续检查权限、精确请求、操作时间、流水与审计，并控制写入与事务回滚。重复调用不会只因状态相同就绕过这些检查。

创建服务通过 `initial_order_status()` 取得 `CREATED`。取消、履约、发货、确认完成和退款服务先调用 `resolve_order_transition()`，在既有权限与证据核验完成后调用 `apply_order_transition()` 写入状态。写入前重新核对当前状态与此前的转换结果；验证后状态发生变化、非法动作或重放路径进入写入入口均拒绝，原事务的积分、库存、物流与审计处理仍由对应服务控制。重放由领域服务校验证据后返回，不再次写状态。

本切片不新增 `RESERVED`、`PAID`、`RECONCILED`、`SETTLED`、`REFUNDING` 等状态，不修改数据库约束或历史订单，不引入对账状态字段或补偿写入。后续需要持久化或新流程时，应单独设计证据、兼容性、迁移及回滚口径。
