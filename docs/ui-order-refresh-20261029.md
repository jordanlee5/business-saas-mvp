# UI第8轮：订单下拉刷新与下一阶段

基线`9a786bf0a4f0cd233c88b4b84c142317d17a2e32`。用户接受订单分页隐藏、风格及兑换流程，要求去掉独立刷新入口并从详情返回列表。

## 交互

- 订单列表移除“刷新订单”和异常时的“重新加载”按钮；下拉页面读取当前列表页码，不重置到第一页，不跳首页。
- 订单详情移除“刷新本单”按钮；下拉重新读取同一个订单。失败后保留订单目标，再次下拉仍核对本单。取消结果不确定时提示下拉核对，不重新执行取消操作。
- “查看全部订单”改成“返回上一页”，从详情回到进入前的订单列表页码。若从提交兑换直接进入详情，没有来源列表，则显示订单列表第一页；不会退回确认兑换页。
- 刷新不触发导航。这里保持的是订单列表页码和详情订单，不承诺刷新后保持像素滚动偏移；下拉手势本身在页面顶部触发。加载/取消操作中不重复请求，结束下拉动画；迟到响应仍遵循页面隐藏及会话隔离规则。重新显示列表时也保留其页码。

## 本机复验

原“开礼优选-UI验收”项目点编译即可，仍是游客离线演示。进入个人中心→我的订单，确认独立刷新按钮已移除。下拉订单列表，仍留在订单列表；进入某单详情下拉，仍为该订单。点“返回上一页”返回订单列表。提交兑换直达详情时，返回按钮也进入订单列表。

在演示控制台选择“订单列表首次断网（重试恢复）”，再进入我的订单；首次失败后下拉刷新，恢复订单列表或空状态。此为模拟失败，不代表真实断网。超过20条订单的页码保留由自动数据验证；原生手势、实际显示仍需微信开发者工具复验。详情页本身没有分页，列表仍在确实超过一页时提供翻页。

## 证据

新增5组下拉刷新检查，订单状态共13组，全客户端共101组；生成演示使用下拉回调恢复。TypeScript、64项专项、778项全量（精确9组PG预期跳过）、独立PG40项无跳过、1组生成UI串联与隔离HTTP5项通过。首轮专项因临时目录权限失败，日志保留，正常本机权限重跑通过；不计失败尝试为通过。真实库只读保持0013，无升级或清理。详见[公开摘要](validation/ui-order-refresh-20261029.json)。本轮没有新增浏览器视觉或真机验收结论。

## 配色与下一阶段安排

保留目前的深绿/渐变绿、米白和暖金积分色。当前商品图是简化演示占位，正式商品照片会带来更多色彩；优先替换真实素材，再按实际页面考虑少量暖色活动图和标签，避免在已验收基础上整体换色。这是设计建议，本轮不变更配色。

两处收尾完成后可从UI打磨转入业务联调及上线准备，建议依次进行：

1. 在隔离环境对接实际后端，验收后台配置商品/规格/库存、会员权益、兑换订单及后台履约/取消/退款的一致性，继续使用明确标识的测试数据，核对演示与真实服务差异。
2. 整理正式商品素材、分类映射、客服信息、供应商代发与运单回传方式；涉及真实供应商接口、凭据或经营决策集中确认，不假称已有对接。
3. 用户注册最终新主体小程序后，再核对最终公司名称和新AppID，单独准备新账号权限及隐私资料；AppSecret仅在本机输入。当前AppID只作临时历史准备配置，不能用旧配置的完成状态代替新账号验收。具体切换见[既有计划](wechat-platform-setup.md)。
4. 正式平台、服务器/HTTPS、上线和真实库0014升级按准备情况及授权另行实施。暂不买服务器、不提交微信审核、不提前启用隐私审核通过标志；六项平台延期继续保留。

此处为下一阶段计划，不代表本轮完成了真实微信、真实供应商或正式部署。保存期限仍待具体定案，真实清理关闭，短期对账数据不清除。
