# M6-9 商城订单确认履约后台入口

## 范围与权限

- 仅启用中的超级管理员、运营管理员可进入商城订单页面和提交确认履约；初审、复核、上传方及停用账号不可操作，直接 POST 也会在调用服务前被拒绝。
- 仅状态 `CREATED`（待处理）的详情显示按钮；提交时再次以既有领域服务锁定并核对订单状态、订单项、预占积分、库存和管理员权限。页面状态只用于展示，不能代替服务校验。
- 列表与详情仍可只读查看各状态；本切片未增加发货、完成、取消或退款操作入口。

## 提交语义

1. 在订单详情核对订单编号、商品、数量与积分，确认后提交表单。GET 返回的表单令牌通过 HttpOnly、SameSite=Strict 的同源 Cookie 与隐藏字段配对；HTTPS 下 Cookie 启用 Secure。
2. POST 验证当前账号、订单权限和令牌；令牌丢失或不匹配时返回详情错误提示，不触发订单写入。
3. 通过验证后调用既有 `execute_order_fulfillment`：一个事务内消费原订单预占的积分、产生不可变积分流水、库存出库流水、推进订单至 `FULFILLING`（待发货）并记录唯一管理员审计；任一证据异常则整体回滚。
4. 已成功确认的相同请求由领域服务幂等重放，不新增积分、库存或审计事实；已取消、已发货等非适用状态失败关闭。完成确认后页面隐藏确认按钮。

后续物流公司与运单号录入、完成、退款各在独立切片开放。真实业务库没有订单时，页面正常显示空状态；验收使用临时 SQLite 和独立 PostgreSQL `_test` 数据库，不为了截图写入真实订单。
