# Level Infinite 事件与本项目云厂商选择

核对日期：2026-11-05。用户询问 NIKKE / Level Infinite PC 启动器 CDN 投毒是否需要改变服务器采购。

## 判断

**目前不建议仅因这件事更换腾讯云。** 已查到的原始研究描述的是特定启动器加载的官方 CDN 脚本被篡改，并指出攻击者如何取得写入权限仍不明确；该材料没有证明腾讯云 CVM 的底层主机或跨租户隔离普遍被攻破。因此继续保留 CVM 4 核 8GB 的测试部署建议。这是基于当前证据作出的采购判断，不是对任何云厂商的绝对安全保证。

[研究者原始报告](https://gist.github.com/MotherSphere/d6c049a09ba8ac3085c51ee9df24a4e5)记载脚本被修改及恶意远程加载链路，并区分已核实与评论区报告的发现。报告链接了[官方首次公告](https://x.com/NIKKE_en/status/2117817602659770434)及后续公告。此次检索直接访问官方 X 后续链接返回 403，因此不将无法直接读取的公告当作独立完成核验的内容；初始入侵方式、影响范围及后续调查仍需关注。

不把“CDN 上的业务文件遭篡改”直接等同为“整个云平台失陷”，也不把更换另一家厂商作为避免发布账号或依赖链风险的充分措施。如果后续调查披露与我们拟使用产品相关的平台级漏洞，再重新评估供应商。

## 对我们部署的实际要求

- 云账号启用多因素验证，区分付款管理与日常部署权限；服务器密钥、仓库凭据、小程序秘密资料不进入聊天或 Git。
- 发布使用经过测试的明确 Git 提交和镜像摘要，保留文件清单与回退版本；正式部署时继续补依赖版本和构建来源核对。当前不能宣称全部依赖都已完成供应链审计。
- 应用、数据库和识别服务按职责隔离；只开放实际需要的入口，数据库及 OCR 服务无公网端口。本轮 OCR 服务不持有数据库密码、不挂载业务卷，只在临时目录处理当前图片。
- OCR 模型在构建镜像时准备；运行中的隔离 OCR 服务只加入内部网络，不需要访问外部下载源。它执行固定程序，不接受用户指定命令或文件 URL。
- 公开商品图片与私有凭证保持各自访问控制；变更图片存储或 CDN 时，再核对写权限、版本记录及缓存更新。
- 继续使用服务器之外的受限备份，并在新环境演练恢复。已有备份工具的摘要能检测备份文件变化，但不等于抵御所有攻击的完整方案。

本轮检查后台模板，没有发现通过外部 URL 加载脚本的 script 标签；这仅是模板范围的检查，不是整个项目的安全审计。上述部署要求在云资源开通后逐项落实，不声称现阶段已在公网配置完成。

如果用于管理云账号的电脑实际运行过涉事 PC 启动器，应按厂商最新指引先排查该设备，再处理可能暴露的账号凭据；仅更换云厂商不能消除管理终端已经受影响的风险。本轮没有扫描用户个人设备或安装任何事件检测程序。
