# M7-26 小程序隐私授权入口

会员微信登录、权益激活和激活后主动登录在取得新的 `wx.login` code 前，先调用 `wx.getPrivacySetting` 查询微信侧的隐私保护指引。若平台要求授权，页面展示指引名称与微信提供的 `open-type="agreePrivacyAuthorization"` 按钮。用户点击后再次查询微信侧状态；只有平台确认不再需要授权，服务层才允许取得微信 code。拒绝、查询失败或平台指引未配置时，本次操作停止，不取得微信 code、不请求会员或激活接口。小程序不保存本地“已同意”标志，也不以自建勾选框替代微信授权。公开商品浏览不受影响。

个人中心和权益激活页提供“微信隐私保护指引”入口，由 `wx.openPrivacyContract` 打开微信平台当前配置的文本。代码中的 `APPROVED_PRIVACY_APP_ID` 当前留空；它必须在后续正式平台配置切片中填写经过确认的准确 AppID，且运行时 AppID 必须与之相等。开发者工具即使返回形如 `wx...` 的 AppID 或看似已经授权的隐私状态，也不能绕过这一门禁。`touristappid` 和其他未经明确批准的 AppID 在查询前即失败关闭；未在微信公众平台完成《小程序用户隐私保护指引》配置时，入口显示受控错误，不伪造指引正文或同意结果。隐私设置及其错误不进入本地持久化、请求正文或日志。

本切片不修改服务端、数据库、激活资格、短期会话或积分账本。不填写真实 AppID、AppSecret、HTTPS 域名，也不借验收操作在真实业务库创建演示数据。没有上述平台配置和可安全交付的真实业务凭据时，微信平台同意弹窗、真机正向激活及会员积分展示验收均记为 `DEFERRED`；静态编译、访客页面、拒绝路径和接口未被调用的门禁可独立核对。正式配置就绪后，须在真机验证同意、拒绝、重新进入、隐私文本打开及激活成功后主动登录，不能把开发者工具模拟结果写成真机通过。
