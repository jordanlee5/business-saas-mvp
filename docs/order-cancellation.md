# M5-3 已创建订单原子取消

## 范围

M5-3 在 M5-2 原子预占基础上提供内部订单取消领域服务。只有订单所属的启用会员可以首次取消 `CREATED` 订单；取消成功后订单进入 `CANCELLED`，同一调用可以安全重放。`FULFILLING`、`SHIPPED`、`COMPLETED`、`REFUNDED` 以及未知状态均失败关闭。本切片不新增 HTTP 路由、会员端页面或管理员订单页面。

取消严格复用订单项、订单积分批次分配以及原始 `RESERVE` 流水。每个 SKU 追加一条库存 `RELEASE` 流水，每个积分批次追加一条积分 `RELEASE` 流水；历史预占流水和订单快照不修改、不删除。释放键由订单公开编号和 SKU 或积分批次编号确定，不接受客户端提供新的业务幂等键。

## 原子性、幂等与失败关闭

`execute_order_cancellation()` 使用独立事务，SQLite 采用 `BEGIN IMMEDIATE`，PostgreSQL 使用行锁。订单状态、库存余额及流水、积分账户及批次余额、积分流水必须一起提交或一起回滚。较低层的 `cancel_created_order()` 不提交，调用方遇到任何异常必须整体回滚。

首次取消前必须证明订单项合计、积分分配合计和订单主记录一致，并逐项验证原始库存、积分预占流水。已取消订单的重放还必须验证整套释放流水存在且内容完全一致；缺失、额外、冲突或被篡改的证据都不能自动补写或修复。

同一订单的并发取消只允许一方创建释放流水，另一方在前一事务提交后读取完整结果并作为幂等重放返回。锁顺序固定为订单、会员、积分账户、SKU 与库存余额、积分批次，避免与下单、积分到期或库存操作形成反向锁序。

## 积分到期边界

存在预占余额的积分批次仍由既有到期服务阻止自动过期，订单取消必须先释放关联预占。释放不会修改原始 `expires_at`，也不会创造新批次或延长有效期。若释放时原批次已到期，`RELEASE` 仍恢复原批次余额以闭合订单证据，随后由既有到期任务按原到期时刻追加 `EXPIRE`；新下单始终排除已经到期的批次。

冻结批次允许释放关联订单预占，但保持 `FROZEN`，不会因取消自动解冻。该规则只适用于尚未消费的预占释放，不改变 `OPEN-006` 关于已消费订单退款的人工处理要求。

## 数据库影响

本切片不新增数据库迁移，继续使用 `0008_order_reservation` 已具备的 `CANCELLED`、积分 `RELEASE` 和库存 `RELEASE` 结构。部署时不需要升级真实业务库，但仍须确认当前数据库 revision 为 `0008_order_reservation` 且结构就绪检查通过。

## 明确不实现

本切片不实现小程序下单或取消 API、购物车、地址、会员端订单页、管理员订单页、积分正式消费、库存出库或退回、履约状态推进、物流、退款、供应商结算和真实测试数据。

其后的 M5-4 已在不改变本取消边界的前提下实现 `CREATED → FULFILLING` 确认履约、积分 `CONSUME` 与库存 `OUTBOUND`，见 [M5-4 订单确认履约](order-fulfillment.md)。

## 验证

专项测试覆盖正常取消、积分和库存完整释放、精确幂等重放、并发重复取消、非本人订单、非法状态、预占证据篡改、释放证据篡改、积分批次异常时整笔回滚，以及原积分批次到期后先释放再按原时刻过期。由于没有结构变化，不执行 Alembic 往返迁移；仍执行静态检查、当前 head/readiness 核验、订单与积分库存相关回归以及全量测试。
