# UI第6轮：商品详情图片、窄屏与断网恢复

基线`8ae6ea79ad9458272957370ec766dd1133644844`。用户已确认北京时间显示，授权继续小轮收尾，保持深绿色、米白、圆角卡片及既有兑换流程。

## 图片失败与重试

商品详情的每张主图/轮播图、介绍图分别处理图片错误。失败后显示“图片暂未加载”或“介绍图片暂未加载”与“重新加载图片”，保留商品文字、规格、库存和加购入口；没有配置图片时显示“暂无商品图片”。单张重试用新渲染键重建图片，维持原受校验URL，不追加外部地址或自动无限重试。每次尝试都有独立标识，旧失败事件、错误索引或页面刷新前的事件不影响新图片。

图片资源确实缺失时，重试仍会显示占位；网络或资源恢复后再尝试。下拉刷新可重新取得整份商品资料和图片地址。图片失败只影响图片展示，不改变真实库存或价格判断。

## 窄屏及断网恢复

长商品名、长规格、连续英文和商品介绍允许换行；规格文字区可以收缩，积分价格区限定宽度并允许超长金额换行。价格与库存可换行，底部操作区预留安全区，正常长度内容继续现有布局。

商品资料读取失败时展示既有重新加载按钮及恢复提示；加载中清空过期商品和可加购规格，连续点击重试只发起一次请求。恢复成功后，以新返回的规格、价格和库存重建选择；原规格不存在时取消选择。请求代次改为页面实例独立，避免另一个详情页卸载时干扰当前页请求；当前页面卸载后的响应仍被丢弃。下拉刷新在成功和失败时都会结束加载。

## 离线演示复验

原“开礼优选-UI验收”项目点编译即可；控制台新增3个纯虚拟场景：

1. **详情图片缺失**：控制台选择后返回商品页、进入任一详情。主图及介绍图使用故意缺失的本地路径，检查占位和重试。该场景中资源一直缺失，重试后再次占位属预期。切回“正常”，用原生返回回到详情并下拉刷新可恢复正常主图。
2. **详情首次断网（重试恢复）**：选择后返回商品页、进入详情，第一次请求模拟失败；点“重新加载”后正常读取。此为虚拟传输失败，不是假称切断真实网络。
3. **详情长文案**：选择后进入详情，在开发者工具切换较窄设备，检查长文字和积分价不遮挡、可滚动到加购。异常长文案及大额积分仅测试排版，不代表真实商品或售价。

完成后在控制台切回“正常”。正式请求与真实图片断网仍需在后续真实接入时验证；不要将演示包的模拟请求或本地图片当公网后端验证。无需更换AppID或上传审核。
