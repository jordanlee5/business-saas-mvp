# 会员专属售价与机构积分隔离（第三轮）

2026-11-18，从5e9436a接续，第三轮代码及独立虚拟验证完成。尚未切换原测试环境或云端，尚未完成用户统一验收。第一轮机构清单、第二轮价格配置与本轮交易隔离构成完整能力，不能拆成不同版本发布。

## 实际行为

- 每次商品请求都由会员会话查验有效资格，并沿“资格→业务记录→已确认批次机构→积分来源机构”核对。前端传入客户编号、机构名或比例不能选择定价。无归属、冲突、资格失效、机构或总公司停用均阻断浏览与新兑换；只有资格有效且没有规则时才按基准价。
- 同时有效的资格可以有多条，但必须属于同一机构。极端多机构有效资格先停止新交易，保留记录供运营核实，不自动选一家、不混用积分。本人历史订单、物流和权益申请入口保持。
- 总公司默认、分支覆盖，明确100%与继承区分，不叠加。商品列表、详情、购物车重算与下单采用同一十进制金额函数：单价先四舍五入到两位，再乘数量。会员接口只返回适用价及不透明版本标识，不返回基准价、成本、比例或其他机构价格。
- 配置保存成功后，新请求立即使用新规则。下单持有机构锁；同时进行的调价等待该笔交易提交，已开始且持锁的订单保留当时价格。保存前开始、保存后提交的新请求也必须通过价格版本、资格和实际单价复核。
- 小程序每30秒核验可见商城页面，并在返回页面时重核。调价会清理旧显示并刷新；同机构保留商品数量供重新确认，切换机构清空购物车。延迟返回的旧价格不能回填。已有未确认订单的查询标记保留，避免重复扣分。
- 规则保存、商品新增/改价都检查零价、单价上限及全部已配置比例。PostgreSQL用事务锁串行核验SKU与调价，包含新增SKU的并发情形。小程序单价和订单总积分不超过9,999,999,999.99；总数量及总成本也检查现有字段边界。成本不随折扣或溢价变化。

## 分账实现与历史兼容

新增institution_grants把每笔积分批次固定到一个已核实机构。原PointsAccount保留为内部流水重算校验总数，不再作为会员可合并兑换的余额。机构余额从该会员、本机构原始批次分别汇总；扣分只在本机构有效批次中按到期先后分配。总公司、分支A1、分支A2是三个独立范围，同一总公司不构成混用例外。

这是对原方案“会员＋机构分账”的兼容实现：没有重建或合并原积分账本，也没有复制一份容易漂移的机构余额缓存。机构批次与原不可变流水共同承担分账；内部合计只用于一致性检查。人工积分调整和到期仍操作原批次，不提供跨机构转移功能。

新增institution_orders记录订单机构名称/代码、适用比例、规则来源/版本及价格标识。订单行保存实际成交单价与成本。取消、履约、退款和状态预检核对每个原扣分批次都属于订单机构；退款使用原实际扣分金额，回原批次，不使用最新比例，也不转到会员下一年度所属机构。原到期限制保持：取消不延长有效期，原批次已过期时自动退款沿用原阻断规则，交运营处理。

后台会员详情新增分机构余额；批次、流水、订单及导出附带机构名称/代码。旧账面合计明确标为内部校验、不可合并兑换。小程序余额只显示当前资格机构；完全没有积分批次的账户仍可读取零余额，但不因此取得商城资格。已有积分但资格失效或冲突时，积分查询停止，运营仍可分账核对。

旧客户端的商品GET仍返回该会员适用价；创建新订单缺少价格标识时拒绝并要求更新/重新核对，不默认按基准价扣分。旧订单的原请求内容与摘要保持，原请求幂等重放、查询和取消继续保留；已成交后资格失效也不妨碍本人查原订单。客户切换不能改变旧订单归属。

## 0025迁移与上线门槛

0025仅增加两张机构快照表及索引，不更新旧业务、积分、流水、库存、订单或成本记录。只从0023已经明确的批次归属回填积分机构；仅当订单每个扣分批次都有证明且属于同一机构时回填历史订单机构（原成交价保持）。缺失、混合归属不猜测，不能新兑换；混合归属旧订单停止自动处理，需要逐笔核实。完全未归属的旧订单可按原分配安全取消/退款，不引入新机构。

有新增快照数据时禁止删除式降级；跨版本回退先检查完整路径。空数据可往返。正式升级前必须另行只读盘点：未归属批次/积分数量、多机构有效资格、混合机构订单及相关待处理退款。未核实记录不得当作正常可用资金。此轮没有读取真实业务库，因此没有宣称真实旧数据已具备迁移资格。

发布前仍需：三轮统一用户验收、Linux符号链接访问边界复验、新候选镜像冻结及独立业务联验、真实旧记录归属核对、执行时一致恢复点与保全新增业务数据。原固定677ce4b镜像不包含0022至0025；不能沿用其测试证明冒充本次新版本。原云端镜像映射缺口保留，不重复归档或冷恢复。
