# 会员专属商城：服务端访问校验

2026-11-06，从 `ef4fba0` 接续。后台确认的名单资格现已用于商品接口、商品图片和新兑换；客户端入口、鉴权图片与清理现已完成虚拟验证，见[第三轮说明](miniprogram-member-entry.md)，微信原生验收仍待完成。真实业务库未写入、未迁移，未进行公网部署或微信审核。

## 本轮访问边界

| 操作 | 未登录 / 伪造会话 | 已登录但没有有效资格 | 已登录且资格有效 |
| --- | --- | --- | --- |
| 分类、商品列表/搜索/分页、详情及 SKU | 401 | 403 | 可访问当前上架范围 |
| 原图、640 缩略图、HEAD、Range 下载 | 401 | 403 | 可访问已登记且当前可见的商品图片 |
| 新兑换与受托发货预览 | 401 | 403 | 按原积分、库存、价格、地址及委托规则处理 |
| 本人订单列表/详情、原请求结果、物流、权益申请 | 401 | 保留本人访问 | 保留本人访问 |
| 他人的订单、包裹和权益申请 | 401 | 404 | 404 |

身份沿用服务端签发的短期会员会话，数据库确认其微信绑定及会员状态。资格每次重新查询数据库，要求已绑定、启用、开始时间已到且结束时间未到；任一有效来源满足即可。令牌内不缓存资格，不能通过传入 `member_id`、`qualified` 或图片 URL 查询参数自行取得资格。余额为零不取消浏览资格。

没有把浏览资格停用转换为 `Member.is_active=False`。全账号停用仍按既有安全规则限制全部会员接口；只停用浏览资格时，历史服务继续保留。名单外且无历史记录的人不会因此得到其他会员的任何记录。

## 商品图片与后台预览

已移除 `/uploads/mall_products` 的公开 `StaticFiles` 挂载。同一 URL 现在由受保护路由处理，以兼容已登记的图片路径；复制链接本身不携带权限。没有新增可转发的签名链接，也不接受查询参数中的会话令牌。

- 会员须提供 `Authorization: Bearer …`，随后校验有效资格、图片登记记录、对应商品、启用状态、上架分类和可用规格/供应商。未登记文件、隐藏图片、下架商品和越界路径不返回图片。
- 已登录且启用的运营/超级管理员通过后台会话预览图片，可维护尚未上架或停用的图片；上传方和审核角色不能用此通道访问，管理员 Cookie 不能代替会员身份调用商品 API。出现无效 Bearer 时不自动降级使用管理员 Cookie。
- 原图与缩略图用同一资格判断。HEAD、Range、条件请求都先校验，不因 ETag 或分段下载跳过权限。
- 商品数据和图片响应，包括拒绝和故障响应，设置 `Cache-Control: no-store, private`；商品/图片另设置 `Vary: Authorization, Cookie`。数据库异常返回 503，不降级开放。

后端权限限制不了用户已经下载、截图或另行复制的内容。旧浏览器/小程序缓存不会因本轮服务端代码自动清除；第三轮已处理账号切换、退出及资格失效时的页面和专用图片缓存清理，仍需原生环境验证。

## 新兑换与并发停用

先确认本人身份及原请求内容。如果相同请求已经形成订单，允许按原记录重查；请求编号相同但内容不同仍拒绝。原请求查不到订单时，属于新兑换，必须有有效资格。

新兑换在同一事务内锁定有效资格，再执行原积分和库存规则；提交前再次校验有效期，过程中到期则整体回滚。PostgreSQL 下停用先提交时，等待资格锁的新兑换重新检查后被拒绝。若兑换先取得资格锁，则先完成这笔已获准兑换，停用随后生效，之后的新请求被拒绝。SQLite 沿用请求起始时的写事务串行化。

资格不写入进程内缓存。独立 PostgreSQL 验证包含一个持续运行的子进程：先读商品/图片成功，另一进程停用后使用原令牌再读得到 403，历史订单接口仍为 200。

## 部署与小程序接续

测试部署仍使用 `app.main:app` 和仓库提供的 Caddy 反向代理；网关不直接挂载商品文件，受保护路径加不缓存响应头。**不得添加上传目录的 `file_server`、Nginx `alias`、公开对象存储/CDN 或绕过应用的图片域名**。本项目尚无已购买公网服务器和现存 CDN；如果将来接入外部存储，需要一起验证鉴权和缓存边界。

本轮没有新的数据库迁移，仍要求 `0018_member_qualifications`。已确认且有效的虚拟会员已经通过实际 HTTP 接口验证；旧真实名单没有自动授予资格，真实库继续只读。切换真实服务前仍需独立的数据库升级及名单核对流程。
