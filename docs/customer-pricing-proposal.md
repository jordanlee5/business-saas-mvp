# 甲方分层定价与积分隔离方案

2026-11-17讨论，2026-11-18用户授权按三轮实施。三轮机构清单、后台比例配置、会员专属售价及积分订单隔离已在独立环境实现并验证，用户统一验收待执行；现有测试及云端尚未切换。详见[第三轮实现](institution-isolation.md)。两项设想需要与积分交易归属一起实施。

用户11月18日补充确认：在已有模板管理中强制会员积分清单填写分支归属，价格规则自后台保存成功起立即生效。名单具体采用登记机构编号、全称和归属地三列相互核验，见[第一轮说明](client-organizations.md)。

## 已确认的业务规则

- 在会员积分一年有效期内，正常情况下同一会员只归属一个甲方，不会同时归属A和B。
- 极端情况下出现跨甲方资格，也不能合并积分使用；A、B名下的交易分别记录。
- 客户有总公司与分支层级：总公司设置默认比例，分支可单独覆盖。分支之间也分别记账，积分不能跨分支合并。
- 比例作用于商城全部商品的基准售价，支持优惠或加价，商品成本不随比例改变。
- 会员仅看到自己所属客户的适用售价，不返回基准价或其他客户价格；确实没有任何适用规则时，才使用基准价。

上述规则是业务约束，不代表现有程序已经具备相应隔离能力。后续讨论可细化操作方式，不能默默取消积分隔离。

## 推荐的定价方式

后台“积分商城”增加“客户与价格规则”。将客户组织与上传账号分开：组织管理总公司、分支关系，上传账号仅表示谁操作名单；一个客户可以有多个操作账号，不能把账号名称直接当作结算归属。

适用顺序为“分支明确配置 → 总公司默认配置 → 基准售价”。只取一个比例，父子比例不叠加。分支明确设为100%表示使用基准价；“沿用总公司”是另一种状态，不能与100%混为一谈。

| 组织 | 配置 | 基准价100积分时的会员售价 |
| --- | --- | --- |
| 总公司A | 默认90%，即9折 | 90积分 |
| 分支A1 | 沿用总公司 | 90积分 |
| 分支A2 | 独立110%，即加价10% | 110积分 |
| 客户B | 本级与上级均无规则 | 100积分 |

成本字段保持原值。后台用“优惠10%”“加价10%”“按原价”这类表述并显示样例价，减少比例填反。保存前预览受影响组织、商品数量和价格，记录操作者、旧值、新值与版本；第二轮已实施用户明确确认的1%～300%售价比例，支持0.01个百分点；必须先预览再确认保存，见[配置说明](client-pricing.md)。首版只做全商品统一比例，分类价、单品特价及多种优惠叠加留到后续。

金额运算建议沿用积分两位小数，按明确的十进制四舍五入规则先算单件价，再乘数量；不能前台和后台各算一套。舍入后不为正或超出字段范围时拒绝规则，不悄悄改成另一价格。

## 会员只能取得自己的价格

服务端从已核验的会员资格、名单业务记录确定客户及分支，不相信小程序传来的客户编号、价格或比例。登录后的首页、列表、搜索、详情、购物车、结算和下单都使用同一归属与价格规则。接口只返回当前适用价；不把基准价或其他客户价格藏在页面、JSON或缓存中。缓存按身份与规则版本隔离，退出或归属变化时清理旧内容。

资格未确认、过期、客户停用或归属冲突时，阻止取得价格和提交新交易，由运营核实；不能把异常归属当成“未配置比例”而回退原价。正常会员自动进入所属客户，不增加日常选择步骤。首版遇到极端多归属建议先阻断新交易、保留全部记录供运营处理；若以后开放身份切换，也必须限定为已核验身份，独立购物车及积分范围。

## 积分与订单也要按归属隔离

客户和分支是交易归属边界；继承同一价格不等于共享积分。每笔积分发放、占用、扣减、到期、取消及退款保留来源组织；订单保存归属组织、实际单价、成本快照及价格规则版本。余额展示和下单只计算当前组织可用积分，同一订单不得从其他组织积分批次补足。退款按原订单实际扣分和原分配批次处理，沿用已有到期及退款规则，不按最新价格退款，也不转入另一组织。

讨论时的旧代码中，`PointsAccount.member_id`唯一，余额按会员汇总；`PointsGrant`按业务记录分批，但下单选取该会员账号下所有有效积分批次，没有客户过滤。因此不能只加一个价格比例或页面开关。需先设计按“会员＋归属组织”维护余额及流水的方案，核对发放、调整、到期、订单、退款、报表和幂等请求的影响，再选择兼容迁移方式。

会员未来年度转到其他甲方时，历史积分批次、订单和退款归属保持原组织，不能因更新会员当前归属而改写旧交易。组织调级、操作账号转移也不能自动迁走历史账。无法可靠追溯组织的历史记录列为待核实，不能猜测分配或混入新组织余额。

购物车中的商品遇到调价，结算时重新计算并提示确认；下单服务再次核验价格版本、资格和积分归属。已成交订单按快照执行。相同下单请求的重试返回原结果，不因调价重复下单或重复扣分。

## 分轮实施建议

1. 确定组织及名单对应关系，建立总公司、分支和账号关联；确认客户归属来源与历史记录处理表，不修改真实数据。
2. 建立后台比例配置、继承预览、权限与操作记录；做隔离虚拟验证，暂不切换商城价格。
3. 同步接入会员价格与积分交易隔离，覆盖整个浏览到退款链路；新能力在完整通过前不向现有测试环境开放。
4. 在独立环境验收A1继承、A2覆盖、B原价、越权请求、积分不足不跨组织补足、归属冲突、调价确认、退款、年度转归属及旧客户端兼容。
5. 迁移演练、恢复准备、用户验收后形成新候选版本；实际部署仍需执行时一致恢复点及明确发布窗口。

已确定名单必须明确机构归属，比例配置保存成功即生效。第二轮已落实单一比例继承、影响预览、版本与生效记录；第三轮完成交易隔离后统一验收。总部直管名单也必须明确组织身份，不能留空。当前不扩大到多级机构、促销叠加或日常多身份切换。
