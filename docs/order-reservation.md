# M5-2 订单创建与原子预占

## 范围

M5-2 在 M5-1 数据基础上提供内部订单领域服务：校验会员和目录状态，固化商品、SKU、供应商、主图路径、积分价与人民币成本快照，并在同一数据库事务内完成 SKU 库存预占和积分批次 FEFO 预占。当前没有新增 HTTP 路由或后台页面。没有启用中主图的商品允许保存空主图快照，目录后续换图不得回写历史订单。

调用方使用 `OrderLineRequest` 提交不重复的 SKU 与正整数数量，并提供最长 128 字符的订单幂等键。完全相同的会员和商品请求可安全重放并返回原订单；同一幂等键对应其他会员、SKU 或数量时失败关闭。

## 原子性与审计

`execute_order_placement()` 使用独立事务，SQLite 写入采用 `BEGIN IMMEDIATE`；订单、订单项快照、积分分配、积分 `RESERVE` 流水、库存 `RESERVE` 流水及两类余额缓存必须一起提交或一起回滚。较低层的 `place_order_with_reservations()` 不自行提交，接入方必须保证异常时整体回滚。

库存流水从 `0008_order_reservation` 起同时保存现存数量与预占数量的增量、前值、后值和共同版本。入库、调整和订单预占都进入同一连续版本链；余额无法从流水重算时停止下单，不能自动修复。

积分只使用状态为 `ACTIVE`、尚未到期且具有可用余额的批次，按到期时间和批次编号执行 FEFO。每个实际分配批次同时生成订单分配记录与不可变 `RESERVE` 流水。账户缓存或任一批次缓存与流水不一致时失败关闭。

## 已确认的结算口径

供应商结算只纳入 `COMPLETED` 且未退款订单，金额使用订单项 `line_cost_amount` 人民币成本快照。`CREATED`、`CANCELLED`、`FULFILLING`、`SHIPPED` 和 `REFUNDED` 均不进入结算。本切片没有实现结算服务。

## 明确不实现

本切片本身不实现小程序下单 API、会员端或管理员订单页面、积分正式消费、库存出库或退回、物流、退款、供应商结算和真实测试数据。其后的 M5-3 已按本切片保存的分配和预占证据实现 `CREATED` 订单原子取消与资源释放，见 [M5-3 已创建订单原子取消](order-cancellation.md)。

## 验证

专项测试覆盖成功下单、目录快照、FEFO 跨批次预占、库存预占、精确幂等重放、幂等冲突、积分或库存不足整体回滚、过期批次排除和无效会员/目录失败关闭。迁移需在临时 SQLite 完成 `0007 -> 0008 -> 0007 -> 0008` 往返和 `alembic check`，并由部署方在独立 `_test` PostgreSQL 数据库执行真实往返门禁。
