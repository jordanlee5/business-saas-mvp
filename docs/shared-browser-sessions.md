# 后台共享会话与多进程准备

2026-11-05，从 `77e70fa` 接续。只在虚拟 SQLite/PostgreSQL 环境迁移与验证；真实业务库继续只读，不购买服务器，不提交微信审核。

## 运营可见的行为

- 在一个应用进程登录后，切换到另一个进程仍保持登录。普通进程或容器重启不会要求所有人重新登录。
- 在任何进程退出登录后，同一个登录凭据在其他进程也失效；其他设备的独立登录不因单次退出而被自动注销。
- 停用账号会同时撤销该账号全部后台会话。恢复启用后需要重新登录，停用前的凭据不会复活。
- 修改密码会撤销旧会话，并为当前设备建立新会话。首次改密要求仍生效。
- 账号角色、管理员级别、启停状态与密码仍逐次从用户表核对，不把权限保存在浏览器或进程内缓存里。
- 会话存储读写失败时返回暂不可用，不退回本地内存授权。退出请求因存储故障失败时，不声称已经退出，恢复后需重试。
- 从历史备份恢复是另一种情况：PostgreSQL 测试恢复工具在新数据库启动应用前清空后台会话，运营需重新登录，避免已退出的旧凭据随备份恢复而再次有效。其他手工恢复路径也必须先在隔离恢复库清空该表；不能只复制数据库后直接启动。

会员小程序继续使用原有独立令牌，不切换到后台会话机制。

## 实现和迁移

新增结构版本 `0017_backoffice_sessions`，增加 `backoffice_sessions` 表。只存随机令牌的 SHA-256 摘要、用户编号、密码摘要的指纹和到期时间，不存可直接使用的登录令牌或明文密码。

后台 Cookie 名称和安全属性沿用原实现：HttpOnly、SameSite=Lax，HTTPS 下 Secure，最长 8 小时。数据库保存跨进程可比较的 Unix 到期时间；部署主机需保持系统时间同步。访问不会自动延长登录期限。

全局最多保存 4,096 条后台会话。新登录清理过期条目，达到上限时淘汰最早到期的条目；PostgreSQL 使用事务级锁保证多个进程同时签发时仍受同一个上限约束。普通读取不获取这把签发锁。SQLite 兼容路径只用于单机与隔离测试，不作为集中业务扩展方案。

账号停用、密码变更和会话撤销在同一个数据库事务提交。新签发还会重新核对账号与密码，避免刚验证完密码、账号状态已变化的请求签发失效凭据。会话授权在请求开始时核对；退出不会强行终止此前已经开始执行的请求。

生产入口直接使用数据库会话，没有环境开关退回内存。原 `BrowserSessions` 类仅保留给隔离旧测试。后台中间件将同步认证查询放到线程池，避免把新增的数据库读取直接阻塞在异步事件循环中。

升级增加空会话表，不回填已有业务，不迁移旧进程的内存会话。部署这个版本后旧登录需要重新登录一次。新表属于短期认证资料，降级会删除该表并使所有后台登录失效，业务记录不删除。

## PostgreSQL 测试环境启用两个 worker

先使用对应代码版本创建全新的虚拟 PostgreSQL 测试环境，或停止既有虚拟环境后备份并迁移到 `0017_backoffice_sessions`。不要在应用运行时跳过结构核对。

从仓库根目录、已经设置秘密目录和镜像的终端执行：

```sh
export STAGING_WEB_WORKERS=2
docker compose -p saas-pg-test-first -f deploy/staging-postgres/compose.yaml up -d --no-build --wait app
```

`STAGING_WEB_WORKERS` 默认为 1，允许 1～4。SQLite 入口仍固定单进程。本轮验证了两个独立应用容器，以及单个 PostgreSQL 测试服务实际启动两个 Uvicorn worker；无需给业务页面增加进程编号或调试入口。

这只是多进程扩展的认证前提。每个进程会独立加载应用及 OCR 模型，也拥有自己的数据库连接池；不能直接把 worker 数量当成性能倍数。后台写操作、图片文件、OCR、连接数和持续负载仍需下一阶段的混合验证。默认数量保持 1，不自动改变已有服务器设置。

## 本轮验证

两个独立应用进程共享新建的 PostgreSQL 测试库，交替把 HTTP 请求明确发送给 A、B：

1. A 登录，A/B 均能读目录；A 打开维护页，B 提交新分类，A 可查到结果。
2. 普通运营无法读管理员管理页，也无法借 B 进程停用其他管理员。
3. A 调整角色后，B 立即按新权限拒绝目录维护；恢复角色后同一有效会话可继续操作。
4. B 退出，旧凭据在 A/B 都被拒绝。
5. 停用账号撤销两个设备的登录，重新启用也不恢复旧凭据。
6. B 完成首次改密后，当前新会话可用，两个旧设备会话都失效。
7. 上传方不能进入后台商城管理，停用再启用同样不恢复旧会话。
8. 过期、伪造和旧版用户编号 Cookie 均被拒绝。
9. 重启一个应用进程后，有效共享会话仍可在两边使用。
10. 暂停数据库时，两边的会话读取与退出返回 503；恢复后可继续验证并全局退出。
11. 通过正式 PostgreSQL 入口启用两个 worker，日志确认两个服务进程，连续访问正常。
12. 重跑备份恢复：业务表和附件摘要不变，普通重启保留后台登录；新实例恢复后后台会话清空，重新登录、会员订单、商品图及私有凭证权限仍正常。

单元及路由测试另核对摘要存储、8 小时过期、容量边界、撤销事务回滚、签发时账号已变化和故障不降级。迁移测试验证旧用户保留、升级与降级后业务记录不变。
