# 后台登录人机验证

2026-11-10：完成腾讯云验证码可选接入，尚未在测试服务器启用真实验证服务。

## 行为

- 启用后，浏览器先完成人机验证，再提交用户名、密码和一次性票据。
- 服务端必须向腾讯云 DescribeCaptchaResult 核验，只有 CaptchaCode 整数 1 且无风险标记才继续检查账户。
- 缺票据、过期、重复、应用不匹配、容灾票据均拒绝；网络故障、配置损坏返回通用错误，不跳过验证。
- 用户取消、脚本加载失败可重试；密码错误需重新验证；页面恢复清空旧票据。
- 不记录票据、验证码配置或认证头。页面仅获得公开应用编号。
- 未设置 ADMIN_CAPTCHA_CONFIG 时保持原登录流程；指定配置文件但无法加载时拒绝登录。

## 启用前准备

1. 在腾讯云验证码控制台创建应用，核对套餐费用后再开通；当前开发没有购买服务。
2. 设置允许访问的测试域名。域名、HTTPS 就绪后使用真实浏览器做一次完整联验。
3. 在服务器仓库目录之外保存 `admin-captcha.json`，限制文件仅运行服务的账户可读。四个字段均为字符串：`app_id`、`app_secret_key`、`secret_id`、`secret_key`。前两项来自验证码应用，后两项来自仅授予所需验证码 API 权限的云访问凭据。不得使用微信 AppSecret，也不要发送到聊天、仓库或构建镜像。
4. 容器部署：将文件只读挂载到 `/run/secrets/admin-captcha.json`，为每个后台应用进程设置 `ADMIN_CAPTCHA_CONFIG=/run/secrets/admin-captcha.json`。本次不修改既有部署环境。
5. 核对反向代理只接受可信上游的客户端地址；应用端口只能由反向代理访问。代码使用 ASGI 客户端地址，不能单靠代码防止错误的代理信任配置。当前 staging 启动器允许代理头，启用前必须核对其隔离网络和代理配置。
6. 检查成功验证+正确密码登录、错误密码、取消、过期票据、重放、验证服务断连、退出后重登。所有进程必须使用相同启用配置。

故障处理：优先恢复配置、网络或额度。已有登录会话不因验证码不可用而主动注销。紧急关闭只能由服务器管理员移除启用环境变量并重启相关进程；没有公共绕过接口。该能力减少自动化登录尝试，不替代强密码、访问限制、监控及请求限流。

## 验证范围及证据

使用临时数据库、虚拟账户、虚拟供应商响应，无真实数据库写入、无真实验证码收费调用。
后端测试覆盖票据校验、故障拒绝、账户和共享会话回归；浏览器以拦截请求模拟验证码，不证明真实供应商已联调。
证据位于 `docs/validation/login-captcha-20261110/`。浏览器复现脚本使用本地渲染的登录模板，真实配置激活后仍需服务端签名与供应商端到端验收。

参考：[Web 接入](https://cloud.tencent.com/document/product/1110/36841)、[服务端核验](https://cloud.tencent.com/document/api/1110/36926)、[计费](https://cloud.tencent.com/document/product/1110/95040)。
