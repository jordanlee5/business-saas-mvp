# UI第7轮：订单空状态与翻页重试

基线`f2faa10d6a5eb034199a9d117a3d21521184f636`。用户已接受商品详情图片、窄屏及恢复体验，继续授权小轮收尾。保持深绿、米白、圆角卡片和既有兑换逻辑。

## 本轮调整

此前空列表或只有一页时仍出现上一页、下一页；请求第二页失败后，重试使用上一次成功的第一页。本轮把列表是否成功加载与加载中、失败、未登录区分开：只有成功返回空列表才显示“还没有兑换订单”，引导继续逛好物。首屏总数不超过20条时隐藏分页。后续页因记录变化返回空列表时提示“这一页暂无订单”，保留返回上一页能力。

每次请求开始保存本次页码，并清空旧列表、总数和就绪标记。失败后点“重新加载”继续请求该页；失败或加载中不能点击上一页/下一页使用旧总数翻页。隐藏页面、会话失效或进入详情时清理列表状态，过期返回不能覆盖新请求。原订单详情直达、取消、收货信息、北京时间、刷新本单保持。

## 原项目复验

1. 在原“开礼优选-UI验收”项目点击编译。编译会重置虚拟内存订单与积分，购物车草稿可能保留；不用更换AppID。
2. 演示登录后从个人中心进入我的订单：无订单时应显示空状态和继续逛好物入口，不再出现无效分页。
3. 兑换一单后查看全部订单：单页订单正常显示，不显示上一页、下一页；详情和取消仍可使用。
4. 顶部“切换演示场景”选择“订单列表首次断网（重试恢复）”，返回商品页，再从个人中心进入我的订单。首次列表请求提示失败，点“重新加载”恢复已有列表或真正的空状态。完成后切回“正常”。

该场景只让一次虚拟订单列表请求失败，不会切断电脑网络，也不调用微信登录或公网后端。第二页失败后仍请求第二页由自动化数据验证，本次未声称已完成微信原生多页验收。
