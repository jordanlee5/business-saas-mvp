# M6-12 商城订单整单退款后台入口

只有启用中的超级管理员与运营管理员可对 `COMPLETED` 订单从详情提交整单退款；初审、复核、上传方与停用账号不能浏览订单或直接 POST。详情显示固化的积分、商品成本、物流和完成事实，退款原因必填且最多 500 字。页面使用 HttpOnly、SameSite=Strict 的同源 Cookie 与隐藏字段配对校验，HTTPS 下设置 Secure。

POST 再次验证角色和表单令牌，调用既有 `execute_order_refund` 独立事务。服务锁定并核对订单快照、履约、发货、完成、积分与库存流水；原子写入 `REFUNDED`、原因、退款时间、原积分批次的 `REFUND`、SKU 库存 `RETURN` 和唯一管理员审计。相同原因的精确重放不重复返还；原因不同则失败关闭。

订单任一明细已进入待确认或已确认的供应商结算批次，或任一原积分批次已到期时，自动退款失败关闭。页面按钮只按订单状态显示，不预先承诺该订单符合全部退款条件；最终判断始终在写入事务内完成。已退款订单显示固化的退款原因与时间，不再展示表单。

本切片继续使用 `0011_supplier_settlement_foundation`，没有迁移、不支持部分退款、人工补偿、结算冲销或小程序 API。真实业务库没有商城订单时只做空状态和权限冒烟；退款写入场景在临时 SQLite 和独立 PostgreSQL `_test` 中验证，不为演示写入真实业务库。
