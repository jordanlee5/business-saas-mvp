# 会员浏览资格：后台第一轮

2026-11-06，从 `c699992` 接续。用户已确认名单核验和微信身份绑定方案，不做零知识证明。第一轮实现后台登记基础；后续服务端已接入资格校验，见[第二轮访问边界](member-catalog-access.md)。小程序入口和图片下载适配尚待第三轮，不能把后台登记等同于客户端已经完成适配。

## 运营操作

1. 甲方通过现有业务上传入口提交商城名单，运营按原流程承接。只有“已承接 / 商城兑换”批次可用于新增资格；本轮不新增另一套重复名单上传入口。
2. 后台“积分商城 → 会员浏览资格”查看来源和批次，点击批次编号，勾选需要确认的记录（每次最多 25 条），按甲方约定填写开始、结束时间及确认原因。时间均为北京时间，开始时刻包含、结束时刻不包含。不擅自给真实名单设默认期限。
3. 尚未激活的记录显示“待会员激活绑定”；会员完成既有的微信身份交换和一次性激活核验后，在同一事务内关联会员。已经激活的历史记录，在运营明确确认资格时依据原积分发放记录和微信绑定关联。没有激活证据时不允许手填 OpenID、手机号或会员编号强行绑定。
4. “查看 / 管理”中可停用、启用或调整有效期，每次须填写原因。旧页面若已被其他操作更新，会拒绝覆盖，需刷新核对。
5. 操作留痕记录动作、经办账号、时间、原因及变更前后状态。随会员激活自动绑定的记录标识为系统动作，并关联该会员；不伪造人工经办人。页面每页 25 条，记录不可经页面编辑或删除。

仅启用的运营管理员、超级管理员有查看及操作权限；上传方、初审、复审、未登录和停用账号不能进入。各写操作重新读取数据库中的操作者权限并校验表单令牌。页面禁止缓存，原因文本经过 HTML 转义。列表仅展示来源、业务编号和会员编号，不展示电话、车牌、OpenID、激活码。备注不要填写个人身份材料。

## 资格规则

- 每条来源业务最多一份资格。重复确认只跳过已有记录，不能重新启用、延长期限或增加重复审计记录。混入其他批次、来源不一致、未承接、现金返利、冻结或过期业务时整批拒绝，不部分提交。
- 浏览资格与积分账户分开：余额为零不会自动取消资格；停用资格不修改 `Member.is_active`、微信绑定、积分或历史订单。未来接入访问限制时，本人历史订单、物流和权益入口仍保留。
- 一位会员可有多个来源资格，任一已绑定、启用且在有效期内的资格即可满足资格检查。停用某甲方来源不会取消其他仍有效的来源。新文件漏掉某人不隐式撤销已有资格。
- 资格确认依据当前已承接商城业务；冻结/过期来源不允许新增确认。已有资格由独立的启停和有效期维护，不随文件缺失、积分耗尽或积分批次到期自动变化。来源资格撤回须运营明确停用并留痕。
- 本轮沿用现有车辆业务激活字段；若引入非车辆名单，应另做相应核验入口，不为新群体强行收集车牌。没有新增身份照片要求。

## 数据库与上线边界

新增迁移 `0018_member_qualifications`，两张表：`member_qualifications`、`member_qualification_events`。既有数据不自动变成已确认资格，也不批量生成新会员。含资格或审计记录时拒绝降级删除；迁移与连接重建仅在独立虚拟库验证。真实业务库本轮未升级，禁止直接启动新代码指向旧真实库。

操作与审计同事务，审计写入失败时回滚整笔确认、变更或关联。PostgreSQL 按行锁和版本号防止重复确认、丢失修改；SQLite 路由在读取前开启立即写事务。激活与关联使用一致的锁顺序。当前留痕为应用层只增不改，不声称能抵御数据库管理员篡改。

第二轮已统一保护分类、商品列表/搜索/详情、规格、原图和缩略图，并在新兑换时校验资格；已有订单重放及后续售后保持本人访问。之后再补小程序入口、资格提示、临时图片和账号切换清理，最后统一验收。完整闭环见[会员专属商城方案](member-only-mall-plan.md)。
