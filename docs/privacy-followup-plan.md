# 隐私指引与受托发货后续开发计划

日期：2026-10-28。状态：业务模式已确认，以下功能待实现；本轮只记录计划，不提交微信隐私审核，不启用隐私审核通过标志，不改变真实数据库。

## 已确认业务边界

- 会员向本公司兑换商品，本公司承担兑换服务责任；供应商只受托直接发货，不是独立商家入驻。
- 按受托处理设计供应商协议、数据授权和用户告知；不能仅因外部代发就机械套用独立信息处理者的共享流程。具体协议、快递转委托关系和实际处理行为仍须一致；若以后改变用途或业务角色，重新评估告知及适用的同意要求。
- 先在本地隔离演示环境验收完整UI，再安排服务器、HTTPS和正式上线。原六项平台DEFERRED保留。
- 用户确认开发者权限及AppSecret本机录入；本机状态检查确认秘密存在，未向微信验证有效性。不得将密钥或私有配置提交到仓库。

## 当前代码事实和填写修正

- 地址删除物理移除地址簿条目；最小审计保留会员/地址标识、动作、时间，不保留姓名电话地址正文。
- 订单收货快照独立保存，不随地址簿修改或删除。目前没有按隐私期限清理、匿名化订单快照及备份的完整机制；不能声称180天/3年自动删除已实现。
- 小程序不读取微信昵称、头像。后台“用户信息（微信昵称、头像）”不能用于替代OpenID/UnionID声明；微信身份标识用自定义信息准确描述。
- 现有地址、手机号、车牌号、订单信息应保留声明；补充必要操作日志及基础运行平台类型。`wx.getSystemInfoSync`的调用只使用platform字段判断开发者工具/真机；不把整份返回对象上传或持久化，不声明不存在的设备追踪用途。
- 自定义信息应覆盖微信身份标识、手填收件人姓名、业务单号/激活码及积分记录，可按后台支持分项添加；若收件人姓名已经明确包含于地址说明，不重复遗漏或扩大范围。
- 截图还包含注销申请的固定文字及十五个工作日处理承诺；这是待落实的用户权益受理流程，不能假称已有自助注销、全部即时删除功能。

## 后续开发项及完成标准

| 编号 | 待开发事项 | 完成标准 |
| --- | --- | --- |
| PRIV-01 | 数据保存期限与处理清单 | 分地址簿、身份绑定/激活、订单交易信息、收货快照、积分/审计、本地未决记录、导出和备份列出用途、起算事件、期限、例外、负责人。具体天数须业务确认；不把所有信息统一保留3年，也不将积分有效期当隐私保存期限。 |
| PRIV-02 | 到期清理及匿名化 | 先生成仅含标识和统计的只读预演报告；对必要字段执行可重试、可审计的清理。有效订单、售后/争议保留和法定保存例外必须被识别，例外到期后重新评估。保证金额、积分、库存、结算和必要交易凭据完整。 |
| PRIV-03 | 收货快照与幂等兼容 | 现有非空约束、请求摘要/幂等重放、会员查询和后台履约必须适配清理后状态，不能用伪造姓名电话占位，不因匿名化导致历史接口崩溃或重复下单。所需真实结构迁移另行备份、隔离演练和确认。 |
| PRIV-04 | 备份、导出及恢复 | 备份/临时导出到期处理，限制访问；恢复备份后重放有效清理记录，避免已删除信息重新进入正常使用。界定离线副本删除时限和例外，不承诺无法做到的即时全副本删除。 |
| PRIV-05 | 供应商告知与查询入口 | 兑换前明确“本公司提供兑换服务、受托供应商发货”，列明必要数据和用途，提供实际受托方名称/联系方式查询；订单详情保留可追溯履约方记录。多供应商订单分别显示，变更有记录。普通告知不伪装为未实现的独立共享同意；如确需单独同意则另行实现并留证。 |
| PRIV-06 | 供应商最小数据授权 | 只允许受托方取得自己负责订单的收件人姓名、联系电话、地址、必要商品/数量及履约标识；不得取得整个地址簿、其他供应商商品、微信身份标识、激活码、车牌、积分或无关业务资料。限制用途、访问/导出和保留期限，撤销委托后失效；记录实际提供和供应商返还/删除凭据。传输方式按最终实现如实声明。 |
| PRIV-07 | 委托协议与快递边界 | 由运营方落实委托目的、期限、方式、数据类型、安全措施、监督、返还/删除义务以及物流转委托授权；后台支持记录受托主体和协议状态。实际承运人的角色另行核对，不把所有外部主体自动认定为同一种关系。 |
| PRIV-08 | 用户权益受理 | 完善查阅、更正、删除、撤回和注销申请入口及人工处理记录，核验身份，按最终指引承诺办理；区分可删内容和必须继续保存的内容，说明理由和用途限制，避免承诺注销即删除全部历史交易。 |

## 排期与验证

先确认表单草稿和具体运营规则，再开发用户可见的受托发货告知、地址删除说明及权益入口，并在隔离数据上纳入UI验收；上线前完成清理、备份、协议与数据授权控制。UI通过不解除平台正向延期，也不等于全部隐私功能通过。

后续代码轮次保留专项、完整回归、规定独立PG和前端检查。重点覆盖跨供应商隔离、多供应商订单、撤销授权、清理边界时刻、异常重试、争议保留、备份恢复、快照清理后的幂等及订单历史、日志和导出不泄露个人信息。

本次仅计划文档变更：检查链接、差异、禁止启用的标志和提交范围，不重复执行业务测试；不将上一轮测试数字写成本轮新跑结果。开发轮次继续独立提交推送GitHub。

## 指引草稿约束

保存期限优先按最短必要原则、分用途确定；若后台只接受统一固定天数，先核对选项，不任填180/1095天。没有落实处理流程前只保存草稿。

受托发货应如实告知，不填写“从不向任何外部主体提供信息”，也不填写“商家入驻”。微信固定“独立共享/转让”条款与受托处理分别核对，不能凭一个“第三方”词直接选是/否；截图未显示该栏完整选项，尚未确定具体按钮。
