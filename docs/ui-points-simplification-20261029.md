# 我的积分：客户展示简化

用户已在微信开发者工具验收并认可订单直达和交易页简化。本轮只调整积分页，保留深绿色、米白背景、圆角卡片与现有导航。首页8分类和四入口导航仍在下一小轮。

## 页面与金额含义

- 顶部保留可用积分，到期提醒明确是“部分可用积分”最近到期时间，不暗示全部积分同日失效。
- 收起会员编号、预占余额、批次数、批次详情和每笔预占变化；不再为页面读取批次接口。
- “积分流水”改为“积分记录”，每条只有事项、带正负号的积分和北京时间。到账/退回用绿色，兑换/到期等减少用原有暖棕色，同时用正负号区分。
- 对照可用积分：GRANT→积分到账；RESERVE→商品兑换；RELEASE→订单取消退回；REFUND→退款退回；EXPIRE→积分到期；ADJUST→积分调整。下单减少可用积分时显示一次，后续 CONSUME 的可用积分变化为0，不再显示为第二次扣减。
- 保留简短解释：提交订单后相应积分暂不可再用，取消成功后退回。没有改扣减/结算时点，也没有向用户展示内部订单或批次编号。多批次涉及的事件仍按实际变化金额分别记录，不把单条分配金额冒充整单总额。

## 接口与边界

原 `/points/ledger` 增加可选 `available_only=true`。默认完整流水行为和响应字段兼容；客户积分页显式选择仅可用余额变化。服务端在统计总数和分页之前过滤0变化，避免内部结算导致空页或错误的总数。当前会员绑定验证、账户/批次缓存对账、只读会话和字段白名单保持。运营完整事件仍保留，不做数据清理或数据库迁移。

页面只读取身份、汇总和客户流水。离开页面即清空展示数据并废弃旧请求；失效会话、分页异常或畸形数据不继续展示旧账户信息。客户端对仅变化视图出现0变化响应拒绝显示，而不是在本地偷偷过滤后掩盖接口分页问题。原完整流水方法仍可供既有调用使用。

独立离线UI演示的内存数据同步采用分页前过滤；保留离线提示、虚拟身份和无原生网络限制。正式隐私批准标志、域名、真实数据库和保存期限策略未改变。

## 验收

新增3项服务端测试覆盖过滤后的金额合计、稳定分页、原接口兼容、会员隔离/停用/缓存异常、实际HTTP查询参数解析；独立PG原积分测试补充结算行位于第一页之前时仍正确分页的断言。

新增9组客户端检查覆盖通俗名称/正负数、空态、分页防重复、页面隐藏、畸形响应、失效会话、跨会话旧响应；生成演示串联检查验证下单→履约完成只有一次兑换记录，退款后有对应退回且余额恢复。

本轮实际检查结果见[验收摘要](validation/ui-points-20261029.json)，完整日志保留在本机 `.runtime/ui-points-20261029/`。脚本检查不等于微信原生视觉、正式微信身份或真实交易验收；新的页面效果由用户在原UI验收项目重新编译后确认。
