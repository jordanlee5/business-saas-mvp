# 按包裹查询物流：虚拟接入验收

日期：2026-11-06；从 `fa98da7` 接续。服务器与域名仍停留在[已保存的采购进度](procurement-and-logistics-plan.md)，等待用户确认实际运营公司。首次部署仍为虚拟数据测试环境，本轮没有采购、写入真实库、切换主体或提交微信审核。

## 本轮实现

会员在订单详情每个包裹下点击“查看物流”，进入独立页面。展示运输状态、按时间倒序的节点、北京时间和查询更新时间；无轨迹、服务尚未开通、查询失败及上次记录均明确区分。失败可刷新重试，退出页面或登录失效后清除数据，过期请求不能重新填回页面。

新增只读接口：`GET /api/miniprogram/v1/orders/{order_id}/parcels/{parcel_id}/tracking`。先验证会员登录、订单归属和包裹确实属于该订单，再查询缓存或适配器。缓存命中也不绕过身份检查；未登录401、他人或错误关联404。响应沿用私有禁止缓存头，不接受客户端提供任意运单号。

复用0015已有的包裹记录，返回包裹编号供客户端定位，不增加数据库迁移。编号不是访问凭据。0015之前只有整单运单、没有包裹清单的历史订单继续显示原运单信息，不伪造包裹或自动补历史轨迹。

物流服务不修改订单、积分、库存或结算。查询前已经释放数据库连接；即使适配器等待，兑换与取消仍可完成。签收仅是轨迹状态，不触发自动完成订单或供应商结算。

## 当前接入边界

正式服务默认 `DisabledProvider`，没有真实供应商密钥或外网请求；返回“物流轨迹服务尚未开通”。虚拟适配器只由隔离测试注入，独立离线小程序演示数据不会进入正式构建。**本轮完成的是查询结构和虚拟流程，不代表已开通百递云或查到真实运单。**

每个网页进程最多2个进行中的适配器调用，不排队等待；同包裹查询去重，最多512个缓存条目。成功记录缓存5分钟、失败后30秒再尝试，旧记录最多显示1小时，并明确标为上次记录。此缓存不跨进程共享、重启不保留，不是服务商计费额度控制。真实接入时需按供应商合同进一步确认共享缓存/额度、严格网络超时、频控和隐私处理依据。

适配器会收到3秒超时参数；当前虚拟测试验证超时异常处理与慢调用并行隔离，尚未验证真实网络超时。真实适配器必须实现总网络超时，不能仅依赖该参数。默认服务没有网络调用；本轮未实现订阅回调、后台自动刷新或真实服务商连接。

## 验证与留证

验证计数和原始日志指纹见[本轮证据](validation/parcel-tracking-20261106.json)。覆盖：

- 两个包裹对应不同轨迹、同一订单不能借用其他订单的包裹；会员A、会员B、匿名和停用会员隔离，已有缓存也不能越权。
- 暂无轨迹与故障区分；缓存、失败冷却、旧记录超期、异常文本不外泄；恢复后重新查询正常。
- 查询等待期间数据库连接已归还，新的兑换、取消正常；查询前后订单状态、积分和库存保持。
- 生产客户端编译及页面逻辑检查；模拟原生请求验证会员会话、非法路径、错误包裹响应、断网重试、页面隐藏和会话过期。
- 独立离线演示串联：虚拟会员兑换两个供应商商品→分两包发货→点击第二包查看轨迹→故障期间继续兑换并取消→恢复查询。禁止真实微信网络调用。

生成的离线演示可导入微信开发者工具，沿用原离线演示的发货推进操作；故障场景支持 `tracking_offline`、`tracking_stale`、`tracking_empty`。本轮页面脚本验证不等同于微信原生渲染或真机验收。
