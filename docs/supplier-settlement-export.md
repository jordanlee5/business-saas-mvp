# 供应商结算查询与审计导出说明

## 1. 本切片目标

M6-4 在结算原子生成与确认之上增加内部只读报告服务：查询供应商结算批次和明细，并为证据完整的已确认批次生成 Excel。

本切片继续复用 `0011_supplier_settlement_foundation`，不新增数据库迁移，不开放 HTTP API 或后台页面，也不增加支付、撤销或冲销状态。

## 2. 列表与详情查询

列表支持按结算编号、供应商公开编号或供应商名称关键词检索，支持全部、待确认和已确认状态筛选，并按生成时间倒序分页。页码和每页数量执行显式边界校验，每页最多 100 条。

详情返回批次汇总和全部结算明细快照，包括订单公开编号、完成时间、商品、SKU、供应商货号、单位人民币成本、数量和行成本。分包订单会在后台核对包裹数量、归属和末包运单，页面和导出均只展示结算所需字段。

PostgreSQL 的详情页在可重复读的只读事务内复核证据。运营查看多笔订单的批次时，超级管理员可同时确认该批次。一次页面请求看到同一时点的数据，刷新后读取最新状态。调用方自行传入会话进行多步只读对账时，应先建立一致快照。生成、确认和记录导出审计时仍会锁定来源订单和明细。

## 3. 读取时证据复核

同一供应商补结时，日期可以与已有批次重叠。已经进入待确认或已确认批次的订单商品行归原批次，补结只纳入剩余符合条件的商品行。区间里所有商品行都已入批时，系统会提示没有未结算明细。

新生成的批次会在生成日志中同时记录北京时间起止值。查看详情、确认和导出时，系统会用这份记录核对批次日期。历史日志只记录了供应商、订单与明细数量、商品数量及成本，仍按原有凭据核对，无法用这些日志反推当初录入的精确日期范围。

按自然月结算时，开始时间填当月 1 日 00:00，结束时间填下月 1 日 00:00，均为北京时间。归属依据是订单完成时间。恰在结束时刻完成的订单计入下一期。Excel 日期单元格与详情页面均显示至秒，导出会直接舍去秒以下部分，以免月末最后一刻被舍入到下月；入批筛选仍使用数据库原始精度。

详情读取会复用生成及确认服务的证据规则，重新验证：

- 批次合计能由全部明细重算，订单数按订单去重；
- 每条明细唯一对应来源订单项，供应商、订单、商品、SKU、数量和人民币成本快照一致；
- 来源订单仍为 `COMPLETED`，无退款事实，完成时间仍位于批次左闭右开区间；
- 生成管理员与唯一 `mall_supplier_settlement_generate` 审计完整一致；
- `CONFIRMED` 批次具有完整确认人、确认时间与唯一 `mall_supplier_settlement_confirm` 审计；待确认批次不得提前携带确认事实。

任何状态、快照、合计、时间或审计证据异常都会失败关闭。

## 4. Excel 内容与数据安全

只有 `CONFIRMED` 批次可以导出。工作簿包含：

- `结算汇总`：结算编号、供应商快照、区间、状态、订单/明细/数量合计、人民币成本总额、生成与确认信息和导出时间；
- `结算明细`：订单公开编号和完成时间、商品与 SKU 快照、供应商货号、单位成本、数量和行成本。

文件只使用结算时固化的成本快照，不受商品目录后续调价影响；不包含会员公开编号、姓名、手机号、车牌号、微信标识、收货地址、物流公司或运单号。以 `= + - @` 或控制字符开头的文本会转义，避免被 Excel 当作公式执行。

## 5. 权限、审计与事务

导出只允许启用中的超级管理员和运营管理员；其他角色、停用、无级别、未知级别或不存在账号均失败关闭。权限在读取明细前验证，避免未授权账号借导出入口获得结算数据。

每次成功生成工作簿均追加 `mall_supplier_settlement_export` 管理员操作日志，记录结算、供应商、订单/明细/数量/成本合计及 UTC+8 导出时间。文件生成、证据核验或审计写入任一步失败时事务回滚，不留下部分审计。

## 6. 当前明确不做

- 不开放结算后台、HTTP API 或浏览器下载路由；
- 不导出会员、地址、物流或微信身份信息；
- 不修改批次、订单、积分、库存或现金返现数据；
- 不标记付款、转账、发票或对账状态；
- 不撤销、删除或冲销结算批次；
- 不把生成 Excel 等同于供应商已收款。
