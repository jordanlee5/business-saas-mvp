# M6-13 商城订单待处理取消后台入口

启用中的超级管理员和运营管理员可在 `CREATED` 订单详情填写必填、最多 500 字的取消原因。初审、复核、上传方及停用账号不能查看订单或直接提交取消。GET 使用同源 HttpOnly、SameSite=Strict Cookie 与隐藏字段配对，HTTPS 下启用 Secure；POST 再次验证账号与令牌。

领域服务在独立事务中锁定订单、管理员、会员、积分与库存资源，核对原订单快照和预占证据。首次取消追加原 SKU 库存 `RELEASE` 与原积分批次 `RELEASE`，推进 `CANCELLED`，将管理员身份写入释放流水并保存包含原因的 `mall_order_cancel` 审计；任一失败整体回滚。原会员自行取消的流水身份与行为保持原状。

相同管理员与原因重复提交会复核全部释放流水和审计后返回首次结果，不产生第二套证据。其他管理员、不同原因、已由会员取消、已进入履约的订单以及证据缺失或冲突均失败关闭。页面状态只控制按钮显示，最终判断在写事务内完成。

本轮继续使用 `0011_supplier_settlement_foundation`，不新增迁移、小程序 API 或真实业务库演示订单。写入场景在隔离的 SQLite 及确认目标的独立 PostgreSQL `_test` 数据库验证。
