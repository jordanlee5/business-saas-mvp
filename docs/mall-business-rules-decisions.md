# 积分商城业务规则决策记录

- 文档版本：v0.5.0-M6-2
- 建立日期：2026-08-27
- 最近更新日期：2026-09-21（已实现供应商结算批次原子生成）
- 适用范围：M1/v0.4.0 及后续积分商城阶段
- 当前状态：已建立订单完整内部生命周期，并可原子生成待确认供应商结算批次；尚未开放订单 API、页面、结算确认/导出、部分退款或异常人工恢复
- 依据：《业务数据管理 SaaS：旧路线图收口与积分商城新路线图》

## 1. 记录原则

本文件只固化商城开发必须遵守的业务决定，并持续记录尚待产品确认的参数。规则状态分为：

- **已确认**：后续设计和实现必须遵守；
- **待确认**：只有推荐默认值，进入对应阶段前必须书面确认；
- **已替代**：保留历史原因，并指向替代决定。

任何影响现金核销、积分余额、库存、订单、退款或供应商结算的规则变更，都应先更新本文件，再进入独立代码提交；不得用代码实现反向替代业务确认。

| OPEN-007 | 运费规则 | 第一期全部包邮，不收取现金或积分运费 | 2026-09-08 | 商品页、购物车、订单快照和积分扣减均不得增加运费项；后续若改变规则必须新建版本化决定，不回写历史订单 |

### 3.2 仍待确认参数

当前没有已进入开发阶段但仍未确认的业务参数。新增参数仍不得由开发者静默采用推荐值；必须先书面确认，再更新本文件和进入代码实现。

## 4. 统计与审计不变量

- 现金已核销、商城已激活、商城已消费、未消费余额和已过期积分必须分别统计；
- 同一来源业务不能同时形成现金最终核销和商城积分入账；
- 展示余额即使使用缓存，也必须能由不可变流水重算且结果一致；
- 人工积分调整、库存调整、发货、退款和供应商结算都必须记录操作者、原因和时间；
- 手机号、车牌号、地址和物流信息按最小权限展示，导出和敏感查看需要审计；
- 订单退款必须同步处理订单状态、积分流水和库存流水，禁止只修改文字状态；
- 供应商结算不得纳入取消、未完成或已退款订单。

## 5. 第一版明确不做

- 微信支付和积分加现金混合支付；
- 多商户入驻、自动采购；
- 优惠券、秒杀、拼团和会员等级；
- 依赖收费物流查询 API 的自动轨迹；
- 把第三方开源商城后端直接连接现有业务数据库；
- 仅凭手机号和车牌号登录、领取或扣减积分。
- 未完成微信服务端登录态与请求级限流前开放公网激活接口，或直接信任客户端提交的 `openid`；
- 一期直接接入短信供应商；短信验证码在发送频控、回执校验和成本责任明确后再启用。

## 6. 决策变更模板

### 2026-09-21：实现供应商结算批次原子生成

- 启用中的超级管理员和运营管理员可以按单一供应商及左闭右开完成时间区间 `[period_start, period_end)` 生成待确认结算；生成时间不得早于区间结束；
- 生成时只纳入仍为 `COMPLETED`、无退款原因与退款时间、且从未进入任何结算明细的订单项；取消、创建、履约中、已发货、已退款、区间外和其他供应商订单项全部排除；
- 批次合计必须从本次纳入的订单项重算，订单数按订单去重；供应商批次快照取生成时供应商信息，明细继续固化订单完成时的商品、SKU、供应商、数量和人民币成本快照；供应商后续停用不免除历史已完成订单的结算责任；
- 批次、全部明细与 `mall_supplier_settlement_generate` 管理员操作日志必须在同一事务保存并回读核验；权限、来源快照、成本算术、合计或审计任一异常时整体回滚；
- 同一供应商的生成操作以数据库行锁串行化，并由 `order_item_id` 全局唯一约束兜底；重复或并发请求没有新增合格订单项时失败关闭，不创建空批次；
- 本切片复用 `0011_supplier_settlement_foundation`，不新增迁移，不开放确认、撤销、支付、Excel、HTTP API 或后台页面，也不改变既有订单退款与现金返现行为。

### 2026-09-18：建立供应商结算批次与成本快照基础

- 结算批次按单一供应商和左闭右开完成时间区间 `[period_start, period_end)` 保存；批次必须至少包含一个订单、一个订单项和一个商品数量，生成时间不得早于区间结束；
- 批次状态一期只登记 `PENDING_CONFIRMATION` 与 `CONFIRMED`。已确认批次必须同时保存确认管理员和确认时间，待确认批次不得提前携带确认事实；
- 每条明细固化订单公开编号、完成时间、商品、SKU、供应商、数量和订单项人民币成本快照；每个订单项最多进入一个结算明细，防止跨批次重复结算；
- `0011_supplier_settlement_foundation` 只新增空表，不扫描或自动纳入现有订单，不改写订单、积分、库存或现金返现数据；存在结算批次或明细时拒绝降级丢失证据；
- 本切片只建立持久化及迁移边界。后续服务仍必须依据 `OPEN-008` 仅选择生成时仍为 `COMPLETED` 且未退款的订单，并在同一事务校验批次合计、权限和审计；本切片不开放生成、确认、Excel、HTTP API 或页面。

### 2026-09-17：实现已完成订单整单退款与双资源恢复

- 启用中的超级管理员和运营管理员可把证据完整的 `COMPLETED` 订单整单退款为 `REFUNDED`；第一版不支持部分商品、部分数量或部分积分退款；
- 退款必须按订单保存的积分分配把积分退回原批次并追加 `REFUND` 流水，按订单项与原出库证据把库存退回原 SKU 并追加 `RETURN` 流水；订单、双资源余额、流水与管理员日志同事务提交；
- 原积分批次在退款时已经到期则整单失败关闭并进入人工处理，不自动延期、不创建临时批次、不转入其他批次；冻结批次恢复余额后仍保持冻结；
- 相同原因的精确重放或并发退款只允许一套事实证据；原因冲突、时间倒置、订单合计漂移或任一预占、消费、出库、物流、完成证据异常时拒绝处理；
- `0010_order_refund_recovery` 为订单增加退款原因、退款时间及状态完整性约束。旧库已有无双资源恢复证据的 `REFUNDED` 订单时拒绝自动升级，存在退款证据时拒绝降级丢失；
- 本切片不开放 HTTP API 或页面，不实现部分退款、换货、到期积分自动补偿、异常人工恢复或供应商结算冲销。

### 2026-09-17：建立订单手工发货与确认完成链路

- 启用中的超级管理员和运营管理员可把证据完整的 `FULFILLING` 订单手工录入物流公司与运单号并推进到 `SHIPPED`，再把 `SHIPPED` 订单确认为 `COMPLETED`；
- 物流公司、运单号、发货时间和完成时间是订单事实证据；首次操作与对应管理员日志必须同事务提交，精确重放或并发操作不得重复产生日志；
- 发货前必须验证订单快照合计、确认履约日志、积分 `CONSUME` 和库存 `OUTBOUND` 证据；完成前还必须验证唯一发货日志及时间顺序，异常时失败关闭；
- `0009_order_shipping_completion` 为订单增加物流与完成证据。旧库中若已有无证据的 `SHIPPED` 或 `COMPLETED` 订单，升级必须拒绝并进入人工审计；有生命周期证据时不允许降级丢失证据；
- 本切片不开放 HTTP API 或页面，不接入付费物流轨迹，不实现退款、退库、异常恢复或供应商结算。

### 2026-09-16：实现订单确认履约与积分消费、库存出库

- 启用中的超级管理员和运营管理员可把证据完整的 `CREATED` 订单确认进入 `FULFILLING`；其他状态失败关闭，重复或并发确认只能重放同一完整结果；
- 确认履约严格复用订单项、积分批次分配和原始 `RESERVE`：每个积分批次追加 `CONSUME` 并扣减预占余额，每个 SKU 追加 `OUTBOUND` 并同步扣减现存和预占数量，不修改或删除原预占流水；
- 订单状态、库存余额及流水、积分账户及批次余额、积分流水和管理员操作日志必须处于同一事务；订单合计、原预占、消费出库、权限或余额异常时整笔回滚；
- 已在有效期内完成预占但履约时越过原到期时刻的批次允许闭合该订单消费，不修改原到期时间；冻结批次不允许消费，只能按取消流程释放；完全消费且无可用或预占余额的批次进入 `EXHAUSTED`；
- 本切片不新增迁移，继续使用 `0008_order_reservation`；不开放 API 或页面，不实现发货、完成、退款、库存退回或供应商结算。

### 2026-09-16：实现已创建订单原子取消与双资源释放

- 只有订单所属的启用会员可首次取消 `CREATED` 订单；取消进入 `CANCELLED`，其他生命周期状态失败关闭，重复或并发请求只能重放同一完整取消结果；
- 取消严格复用订单项、积分批次分配和原始预占流水，每个 SKU 与积分批次分别追加不可变 `RELEASE`，不得修改或删除原 `RESERVE`；
- 订单状态、库存余额及流水、积分账户及批次余额、积分流水处于同一事务，任一证据、余额或状态异常都整笔回滚，不自动补写异常证据；
- 释放不修改积分批次原到期时刻；已到期但被预占阻止处理的批次先释放关联预占，再由既有到期任务按原时刻核销，不延长有效期；冻结批次释放后仍保持冻结；
- 本切片不新增迁移，继续使用 `0008_order_reservation`；不开放 API 或页面，不实现积分消费、库存出库、发货、退款或供应商结算。

### 2026-09-15：确认供应商结算口径并建立订单原子预占

- 供应商只结算 `COMPLETED` 且未退款订单；取消、创建、履约中、已发货和已退款订单不进入结算，金额取订单项固化的人民币成本快照；本切片只登记规则，不实现结算批次或付款；
- 下单按一个幂等请求创建订单和目录价格成本快照，同一会员、SKU 与数量的重复请求返回原订单，不重复预占；同一键携带不同请求时失败关闭；
- 库存按 SKU 预占并追加不可变 `RESERVE` 流水；流水同时保存现存和预占数量的前后值、增量、版本、会员和订单来源，可从完整流水重算两个余额；
- 积分按未到期有效批次 FEFO 预占并追加 `RESERVE` 流水，订单保存实际批次分配；缓存和流水不一致、积分不足或库存不足时整笔订单回滚；
- 本切片只提供内部领域服务，不开放小程序 API、页面、取消、释放、消费、发货、退款或供应商结算。

### 2026-09-14：接入库存管理后台

- 超级管理员和运营管理员可从左侧“积分商城—库存管理”进入独立页面；页面路由、入库和调整路由使用同一库存细权限，初审、复核、上传方、停用或无效账号不得打开数据库事务；
- 页面按 SKU 展示现存、预占、可售、阈值、库存状态、余额版本、流水数量及账实一致性；未操作 SKU 只读显示零库存，不因查询创建余额行；
- 入库和人工调整继续调用 M4-5 领域服务，页面不直接更新余额；操作者只取服务端登录会话，幂等请求号由页面生成，余额、流水和管理员日志在同一请求事务提交或回滚；
- 账实异常时页面显示异常并停止对应 SKU 写入，服务端提交时再次核验；不得借页面自动修复余额、补写流水或删除异常证据；
