# 供应商结算批次原子生成说明

## 1. 本切片目标

M6-2 在 M6-1 的 `supplier_settlement_batches` 与 `supplier_settlement_items` 持久化基础上增加内部领域服务，允许商城运营角色按单一供应商和完成时间区间生成待确认结算批次。

本切片不新增数据库迁移，不开放 HTTP API、后台页面、结算确认或 Excel，也不改变订单退款与现金返现链路。

## 2. 生成口径

调用方必须提供供应商、左闭右开区间 `[period_start, period_end)`、生成管理员和生成时间。生成时间不得早于区间结束。

服务只纳入同时满足以下条件的订单项：

- 订单在生成时仍为 `COMPLETED`；
- 订单没有退款原因或退款时间；
- `completed_at` 位于指定区间内；
- 订单项属于指定供应商；
- 订单项从未进入任何供应商结算明细。

取消、创建、履约中、已发货、已退款、区间外、其他供应商以及已经结算的订单项均被排除。区间内没有新增合格订单项时明确失败，不创建空批次。

供应商即使在订单完成后被停用，历史合格订单项仍可结算；目录后续改名、调价或停用不会回写订单项及结算明细快照。

## 3. 原子写入与快照

生成服务在同一事务内完成：

1. 校验操作者、时间区间和供应商；
2. 锁定操作者、供应商及合格订单项；
3. 校验来源订单状态、退款事实、完成时间和订单项成本算术；
4. 按订单去重计算订单数，并重算明细数、商品数量和人民币成本总额；
5. 创建 `PENDING_CONFIRMATION` 批次；
6. 逐项复制订单公开编号、完成时间、商品、SKU、供应商、数量及人民币成本快照；
7. 写入 `mall_supplier_settlement_generate` 管理员操作日志；
8. 回读批次、明细合计和审计证据，全部一致后才允许提交。

任何一步失败，批次、明细与操作日志整体回滚。

## 4. 权限与并发

启用中的超级管理员和运营管理员可以生成待确认批次。初审、复核、上传方、停用管理员、缺少级别或未知级别账号一律失败关闭。

同一供应商的生成操作通过供应商行锁串行化；`supplier_settlement_items.order_item_id` 的全局唯一约束继续作为数据库兜底。因此相同来源订单项不会进入两个批次。重复或并发请求在首个事务成功后会因没有新增合格订单项而失败，不产生第二套事实。

## 5. 当前明确不做

- 不确认、撤销、支付或冲销结算；
- 不开放结算 HTTP API 或后台页面；
- 不生成或下载 Excel；
- 不处理已进入结算后的订单退款；
- 不引入供应商门户、自动采购或真实测试数据。
