# 商品列表缩略图与部署前图片准备

2026-11-06，从 `7ce1340` 接续。路线图在混合压测后留下了图片传输优化，本轮完成上传时生成缩略图及列表取图。正式目录访问范围尚未改变；会员专属商城另见[规划方案](member-only-mall-plan.md)。

## 行为

- 新上传的主图、轮播图、详情图都生成一份最长边 640 像素的 WebP 缩略图，保持比例、透明度，不放大小图。每种用途都生成，确保运营后来切换主图用途时可直接使用。
- 大图仍使用既有最长边 2400 像素、质量 88 的处理方式；缩略图质量 80。详情接口及后台图片管理保持大图，后台 SKU 列表与小程序商品列表优先返回缩略图。
- URL 保持现有目录结构，缩略图为原文件名加 `.thumb-640.webp`。没有新数据库字段或迁移。
- 旧图片或缺失缩略图时自动使用原图；浏览请求只检查文件是否存在，不现场解码或压缩图片。不自动改写真实图片与业务库。历史图片批量补图另行安排，现有旧图不会凭本轮提交自动变小。
- 两份文件先写临时文件，再发布；任一保存或发布失败会清理本次生成的文件。数据库保存失败时继续由既有上传流程调用清理函数，同时删除缩略图。删除及替换旧图也清理配套缩略图。
- 保留现有格式、5MB、8000边长及3000万像素限制，限定专用目录，不允许路径穿越。缩略图不保留源 EXIF 信息。采用既有 Pillow 依赖，不新增包。

注意：当前静态图片本来就是公开资源，下架商品不等于已知图片 URL 立即失效。本轮不是图片鉴权改造；未来会员专属模式必须同时关闭原图、缩略图和旧静态直链，不能只给目录 API 加登录。

## 验证和重放

专项覆盖新上传文件对、比例与透明度、元信息清除、小图不放大、旧图回退、失败后无孤立文件、删除清理；HTTP 串联验证商品列表取小图、详情取大图、静态下载、下架目录过滤及清理后的404。后台原有上传、权限、失败回滚与商品管理回归仍执行。

运行下列命令时须使用隔离代码副本和虚拟库；不要在真实业务目录直接运行演练或测试：

```sh
python -m unittest test_product_media_storage test_public_catalog_service test_catalog_routes test_catalog_connection_release -v
python -m tools.rehearse_product_thumbnails --output /tmp/new-virtual-image-evidence
```

演练目录必须尚不存在。工具只生成虚拟图，用16个线程完成100次进程内HTTP取图，逐次核对状态与完整内容，保留文件大小和摘要；不连接数据库、微信或物流商。结果的10Mbps时间是“字节数÷理想带宽”的计算，不是真实网络测试，也不代表100人并发业务容量。

本轮固定虚拟纹理样本大图939,980字节、小图3,512字节；这张人工样本缩小99.63%，不能推广为所有商品图的压缩率或实际提速比例。图片内容、尺寸、透明度会改变结果；正式商品图清晰度、首次加载、缓存和公网出口还需在测试服务器复验。该样本缩略图已经查看，图形比例与透明/裁切专项检查通过，但没有替用户重新验收真实商品照片。

具体检查计数、日志摘要与只读指纹以[本轮证据](validation/product-thumbnails-20261106.json)为准。本轮没有购买服务器、部署公网、修改主体或提交微信审核。

依据：[Pillow 图片缩放接口](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.Image.thumbnail)、[WebP 编码参数](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html#webp)。
