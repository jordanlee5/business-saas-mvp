## 隐私指引填写依据

以下来自代码中的实际用途，是后台填写的核对依据，不是替运营主体确定法律承诺或保存期限。

| 数据 | 来源及用途 |
| --- | --- |
| 微信身份标识 | 用户主动登录/激活后，服务端以临时 code 换取 openid；用于会员绑定、本人身份识别。微信 session_key 不返回前端；应用自身短期会话在内存中使用 |
| 业务单号、手机号、车牌号、激活码 | 用户手填，核验既有业务权益并激活绑定；不调用微信手机号获取能力 |
| 收件人姓名、电话、省市区、详细地址 | 用户手填地址簿；用于兑换收货。下单会生成独立地址快照，之后修改或删除地址簿不会更改历史订单 |
| 兑换商品、积分和订单履约记录 | 用于兑换、积分记账、库存预占、订单查询、发货、取消和退款处理；实际履约涉及的承运方/供应方及对外提供方式由运营主体核实 |
| 本地购物车及未决提交标识 | 商品编号、规格、数量、会员公开编号及请求编号，用于购物车和断网重试。收货地址、电话、令牌不写入这些本地持久记录 |

当前没有接入微信位置、通讯录、相册、头像昵称或微信收货地址读取功能；不要为了通过配置而声明并申请未使用的能力。手填个人信息仍须如实反映在隐私指引中。

## 本机服务端配置

`app.wechat_local` 是本机辅助入口，不是生产部署或平台审核工具。使用项目独立 Python，在仓库根运行，`PRIVATE_DIRECTORY` 应为仓库外**尚不存在的专用目录**，其父目录须已存在：

```text
python -m app.wechat_local --directory PRIVATE_DIRECTORY initialize
python -m app.wechat_local --directory PRIVATE_DIRECTORY configure-secret
python -m app.wechat_local --directory PRIVATE_DIRECTORY check
python -m app.wechat_local --directory PRIVATE_DIRECTORY serve
```

本机已准备双击入口，路径见本机交接记录，无需在聊天里录入秘密。初始化只执行一次：创建限制普通其他用户访问的目录（当前 Windows 用户及系统/管理员保留权限），写入公开 AppID、空 AppSecret 和随机生成的服务端会话签名密钥。已存在目录一律拒绝初始化，防止无意轮换签名密钥。AppSecret 通过交互终端隐藏输入两次，不接受命令行值或有回显的输入回退；更新 AppSecret 保留签名密钥。

`check` 只显示布尔状态和公开 AppID，**不会向微信验证凭据**。`serve` 要求 AppSecret 已录入、前后端 AppID 匹配、原有本机数据库存在；只将白名单配置传给本次服务进程，固定监听 `127.0.0.1:8000`，不改系统环境变量、不自动迁移数据库、不创建示例数据。应用启动仍执行结构就绪检查；访问日志关闭。配置文件仅应在此电脑保管，切勿提交或随代码分享。此入口不适用于正式公网部署。

## 验收与证据边界

本轮自动化检查覆盖正式 AppID 与服务端配置匹配、秘密不回显、重复初始化保护、密钥更新保持签名密钥、隔离进程环境、缺少数据库拒绝启动，以及真实客户端代码在隐私标志为空时阻止登录/激活/请求。前端模拟均为离线测试。

平台就绪后的统一微信开发者工具验收为：公开浏览 → 购物车 → 隐私同意/拒绝 → 真实会员激活/登录 → 地址维护 → 确认兑换 → 重复提交/断网恢复 → 会员订单 → 后台发货/完成/取消与退款联动。再补真机 HTTPS 验收。真实库不注入测试数据，演示数据另用隔离库；真实会员和商品须使用经确认的业务资料。

原六项仍为 DEFERRED：真实商品增减移除、购物车返回重取真实详情、正式隐私正向、真实会员正向、正式会员地址正向、HTTPS 合法域名及真机正向。
