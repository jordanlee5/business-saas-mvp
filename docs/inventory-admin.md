# 库存管理后台

## 1. 页面范围

M4-6 在 M4-5 库存余额、不可变流水和领域服务之上新增独立管理员页面：

```text
GET  /mall-inventory
POST /mall-inventory/skus/{sku_id}/receive
POST /mall-inventory/skus/{sku_id}/adjust
```

超级管理员与运营管理员可以进入和操作；初审管理员、复核管理员、上传方、停用账号及无效级别账号均拒绝。导航入口与路由使用同一个 `can_manage_mall_inventory()` 细权限，不继承商品目录页面权限或传统运营权限。

本轮不新增迁移，不修改 `0006_inventory_foundation`，也不预置商品、SKU 或库存测试数据。

## 2. 库存概览

页面按 SKU 展示：

- 商品、SKU 与供应商稳定编号和名称；
- SKU、供应商启停状态；
- 现存、预占和可售数量；
- 低库存阈值及正常、低库存、无库存状态；
- 余额版本、流水数量和账实一致性。

支持按商品、SKU、供应商关键词查询，按库存状态筛选，并限制每页 10、20 或 50 条。汇总卡片始终基于全部 SKU 计算，便于在任意筛选条件下看到全局低库存、无库存和账实异常数量。

迁移不会为既有 SKU 自动创建零余额行。未发生库存操作的 SKU 在页面上只读显示为现存、预占、可售均为零、状态为“无库存”，查询不会据此写入 `inventory_balances`。

## 3. 入库与人工调整

页面不直接更新余额。两个表单分别调用 M4-5 的：

- `receive_inventory()`：只接受正整数入库；
- `adjust_inventory()`：只接受非零整数增量，负数表示盘点减少，正数表示盘点增加。

操作者编号只从已认证服务端会话取得，表单不能指定管理员。页面为每个表单生成独立幂等请求号；同一完整请求被浏览器重复提交时，领域服务安全重放且不重复增加余额、流水或管理员日志。请求号被其他操作者、SKU、类型、数量或原因复用时失败关闭。

余额、流水和 `mall_inventory_receive` / `mall_inventory_adjust` 管理员日志在同一请求事务提交。校验或权限失败、库存不能降到预占数量以下、账实异常、数据库锁及唯一冲突都会整体回滚。未预期异常回滚后继续抛出，不能伪装成成功。

## 4. 流水与异常

库存流水可查看全部 SKU 或筛选一个 SKU，每页固定显示 20 条，按操作时间和内部编号倒序排列。页面展示稳定流水编号、类型、数量增量、变动前后数量、余额版本、原因、操作者和 UTC+8 时间，不展示幂等键，也不提供流水编辑或删除入口。

概览继续调用 M4-5 账实核对逻辑。余额数量、版本或流水链任一不一致时：

1. 页面明确显示“账实异常”；
2. 隐藏该 SKU 的入库和调整表单并显示“已停止写入”；
3. 服务端写路由仍会再次核验并拒绝；
4. 不创建修复流水，不覆盖余额，不删除异常证据。

## 5. 本轮明确排除

- 商品或库存 Excel 导入导出；
- 订单预占、释放、出库、取消或退回；
- 退款和供应商结算；
- 小程序商品、库存或下单接口；
- 真实库存样例数据；
- 对现金返现上传、OCR、审核、核销、统计和结算链路的任何修改。

## 6. 验收建议

专项测试：

```powershell
python -m compileall app migrations
python -m unittest -v `
    test_mall_domain.py `
    test_mall_governance.py `
    test_inventory_service.py `
    test_inventory_routes.py `
    test_inventory_migration.py `
    test_catalog_routes.py `
    test_schema_readiness.py
```

页面冒烟至少覆盖：

1. 超级管理员和运营管理员可见“库存管理”入口，其他角色不可见且直达路由跳回工作台；
2. 当前目录为空时页面正常显示空状态且无 500；
3. 建立 SKU 后，未入库时显示无库存但数据库不自动新增余额；
4. 入库后余额、流水和管理员日志各增加一次，重复提交不重复增加；
5. 正负人工调整、低库存与无库存状态符合阈值口径；
6. 流水 SKU 筛选、分页、操作者和 UTC+8 时间正确；
7. 账实异常时页面标红并阻止后续写入。

本轮没有迁移，已处于 `0006_inventory_foundation` 的真实数据库不需要再次升级；仍应先运行专项测试与页面冒烟，收口前再运行全量回归和只读数据库核验。
