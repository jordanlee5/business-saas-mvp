# M6-10 商城订单手工发货后台入口

## 范围与权限

- 仅启用中的超级管理员、运营管理员可查看商城订单并录入发货；初审、复核、上传方和停用账号的直接 POST 在调用领域服务前拒绝。
- 只有状态为 `FULFILLING`（待发货）的详情显示表单。已发货订单显示固化的物流公司、运单号和发货时间，不再显示发货表单。
- 本切片使用现有 `0011_supplier_settlement_foundation` 结构；不新增迁移、不开放完成确认、退款或付费物流轨迹。

## 发货流程

1. 管理员核对订单、商品及数量后手工输入物流公司和运单号（均为必填，最多 100 个字符）。页面使用同源 HttpOnly、SameSite=Strict Cookie 与隐藏字段配对的表单令牌；HTTPS 下 Cookie 设置 Secure。
2. POST 先验证管理员身份、角色和表单令牌，再调用 `execute_order_shipping`。服务在独立事务中锁定订单、验证原履约、积分消费及库存出库事实，确保同一物流公司与运单号没有用于其他订单，并原子保存 `SHIPPED` 状态、物流事实及唯一管理员审计。
3. 有效的完全相同请求由领域服务幂等重放，不覆盖首次发货时间或产生第二条审计；不同参数、错误状态或证据异常失败关闭。失败返回订单详情错误提示，成功跳回详情。

真实业务库尚无商城订单时，列表空状态是预期结果。验收发货路径在临时 SQLite 与独立 PostgreSQL `_test` 中进行，不为页面测试创建真实订单。
