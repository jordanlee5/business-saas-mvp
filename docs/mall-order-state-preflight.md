# M6-16 订单状态的只读证据预检

## M6-16-2 待处理与已取消

`inspect_unfulfilled_order_state(db, order_public_id=...)` 是内部领域服务，调用方应在一致的数据库读取快照中使用无待写入变更的 Session。仅支持 `CREATED` 与 `CANCELLED`，不开放 HTTP 路由或管理员页面，也不自动修改订单。

预检重算订单项、人民币成本、数量及积分批次分配合计，验证账户和 SKU 库存余额与流水一致；然后复用现有服务检查预占、释放及取消管理员审计，同时拒绝意外出现的履约、发货、完成或退款证据。会员取消没有管理员取消审计；管理员取消必须有匹配的审计与资源释放操作者。证据异常时抛出错误，不会跳过或补造证据。

返回订单编号、状态、订单项及分配数量、取消管理员编号（如有）和释放流水编号，供后续只读异常诊断使用。本切片不判定异常自动修复方案，不验证 `FULFILLING`、`SHIPPED`、`COMPLETED`、`REFUNDED` 的完整链路。已完成订单的四账核对继续使用现有 `reconcile_completed_order`。

自动化测试使用临时 SQLite 验证会员和管理员取消、残留审计、释放流水篡改、脏 Session 和不支持的状态。真实业务库仅可按既有流程做 `mode=ro` 预检；不为本功能创建演示订单。

## M6-16-3 待发货与已发货

`inspect_in_progress_order_state(db, order_public_id=...)` 是内部领域服务，仅接受 `FULFILLING` 与 `SHIPPED`。调用方应在一致的数据库读取快照中使用无待写入变更的 Session；该函数不创建订单、不补写流水、不提供 HTTP 或管理页面入口。

预检重算订单项、成本、数量及积分分配合计，核验积分批次属于订单会员账户，以及账户与 SKU 库存余额可由流水重算。已有履约审计须唯一且与消费积分、库存出库的操作者一致；每个订单项和积分批次必须恰好有一套预占及出库/消费证据，多余释放或退款流水同样失败。`FULFILLING` 不得已有发货信息；`SHIPPED` 须有匹配的唯一发货审计，且发货时间不得早于确认履约时间。两种状态均不得有取消、完成或退款审计与字段，也不得有提前生成的供应商结算项。

返回订单编号、状态、订单项及积分分配数量、履约操作者与审计编号、发货审计编号（待发货为空）、积分消费及库存出库流水编号。证据不完整或冲突时抛错，不做自动修复。`COMPLETED` 的四账核对继续使用 `reconcile_completed_order`；`REFUNDED` 的完整只读诊断留待独立切片。

专项测试在临时 SQLite 验证两种正常状态、只读 SQL、脏 Session、跨状态审计、流水篡改和时间倒置；独立 PostgreSQL 测试库在 `REPEATABLE READ READ ONLY` 事务中复核真实履约、发货证据。真实 SQLite 业务库只做既有 `mode=ro` 结构预检，不为展示创建商城订单。
