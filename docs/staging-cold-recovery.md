# 实际云端镜像归档与全新环境恢复演练

从 `66882d9` 接续，使用测试服务器上实际运行版本的镜像，以及北京时间 2026-11-11 凌晨的虚拟数据备份，在另一台电脑的独立空 Docker 引擎恢复。没有重启、暂停或替换云端验收后台。证据见 [脱敏验证记录](validation/cloud-image-cold-recovery-20261111.json)。

## 本轮完成

- 在云端固定已有恢复点副本，按备份中的精确镜像 ID 导出无标签应用镜像。仅导出镜像和复制已有备份，不另行触发会暂停应用的备份任务。
- 通过 SSH 限速 128 KiB/s 传输。可以用已有文件做差量传输种子，但种子不作为可信镜像；最终文件必须与云端归档的完整大小、SHA-256 相同，并重新校验配置及所有镜像层。
- 目标是另一台电脑 WSL 中的独立 Docker 引擎。开始时镜像、容器、数据卷均为空；随后离线装入 PostgreSQL 基础镜像，再从实际云端归档加载应用镜像。未借用默认 Docker 引擎的应用缓存或数据卷。
- 恢复到全新项目、新数据库和文件卷，并生成独立数据库密码。备份中的历史后台会话被清除，原有管理员密码哈希保持不变；登录检查使用仅在演练库创建的随机临时账号。
- 首次恢复后 29 项 HTTP 业务检查通过；重启演练环境的数据库、OCR 和应用后，39 张业务表与 5 个业务文件摘要不变，再次通过 29 项检查。完成后停止演练服务，保留私密恢复资料。
- Windows 69 项组合检查中 68 项通过、1 项按平台跳过；Linux 69 项全部通过。

检查覆盖：健康、未登录商品及图片拒绝、有效资格商品及图片访问、兑换、重复请求幂等、本人订单与他人隔离、资格停用及到期拒绝新浏览/兑换但保留历史、权益申请人工处理结果、取消返还积分和库存、后台首次改密及退出会话失效。没有调用真实微信或物流服务。

## 以后如何恢复

1. 选择完整且可信的数据库/业务文件恢复点，找出对应的应用镜像归档，同时准备部署配置、兼容的 PostgreSQL 基础镜像和独立私密凭据。
2. 在新的隔离 Docker 环境核验并加载归档：`python3 -m tools.staging_image_archive load --backup <恢复点私密目录> --bundle <镜像私密目录>`。
3. 将 `STAGING_APP_IMAGE` 设为加载结果中的 `runtime_image_id`。设置仓库外 `STAGING_SECRET_DIR`，使用全新 `saas-pg-test-*` 项目运行 `tools.staging_pg_backup restore`，并传入 `--image-bundle`。参见 [镜像操作说明](staging-image-archive.md) 和 [PostgreSQL 部署说明](postgres-staging.md)。
4. 先核对完整性、服务健康、会话废止和原密码保留，再以专门的虚拟数据环境验证业务。`tools/verify_cold_virtual.py` 仅接受明确标记的云端虚拟数据副本，不用于真实会员库。
5. 验证成功之后再单独安排切换；恢复工具不会覆盖现有项目或自动切换访问入口。

现场在云端 `/srv/saas-image-archives/20261111` 与本机 WSL `/root/saas-rehearsal-evidence/cloud-cold-20261111` 私密保存。不要把原始备份、归档、诊断日志或凭据加入 Git。恢复点仍在保留期内时，其应用镜像归档也应保留。

## 明确边界与下一步

本轮证明实际云端副本可以在另一台机器的空容器引擎恢复；不是新装物理机/操作系统演练，也不是整机快照恢复。独立引擎无外网出口、没有发布应用或数据库端口。实际云端三个服务的容器 ID、启动时间保持不变，健康正常；原有备份、巡检和本机小时拉取任务保持不变。

本轮没有安装新的镜像定时归档或镜像轮换任务。后续仍需：全天在线异机存储、备份加密与独立密钥管理、独立外部存活监测，以及新版本发布时将对应镜像归档纳入发布流程。备案通过后再安排域名、HTTPS 与真机接入验证。

真实业务库未接触，备案通过前不开放公网域名，未提交微信审核。GitHub 只保存工具、检查代码和脱敏证据。
