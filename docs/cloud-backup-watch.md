## 检查与提醒

独立任务约每 5 分钟检查备份服务和计时器、最近执行、最近成功恢复点的完整性及新鲜度、应用/数据库/OCR 健康和磁盘。故障不自动重启或修改业务数据。

| 情况 | 行为 |
| --- | --- |
| 备份失败、定时器停用、状态损坏或校验不通过 | 留存固定故障码并尝试通知 |
| 最近成功恢复点超过 36 小时或首次等待期后仍无备份 | 告警 |
| 任务运行超过 15 分钟 | 告警；正常备份暂停应用的 15 分钟内抑制该应用告警 |
| 磁盘空闲不足 5 GiB 或 10% | 告警 |
| 同一故障持续 | 成功发出首次通知后，6 小时补提醒一次 |
| 故障恢复 | 发一次恢复通知 |
| 发送失败或未配置 | 保留本地记录，下轮重试；不记录为发送成功 |

## 运维检查与暂停

以下命令只在测试服务器执行。查看计时器和最近巡检：

```sh
sudo systemctl list-timers 'saas-staging-backup*'
sudo cat /srv/saas-backups/watch/saas-pg-test-cvm/latest.json
sudo systemctl status saas-staging-backup@saas-pg-test-cvm.service
```

凌晨需要验收时，提前暂停备份定时器：

```sh
sudo systemctl disable --now saas-staging-backup@saas-pg-test-cvm.timer
```

这只阻止未来触发，不会停止已经运行的备份。不要强制杀死正在备份的服务；先查看状态。巡检仍会报告定时器停用，属于预期提醒。测试结束后恢复：

```sh
sudo systemctl enable --now saas-staging-backup@saas-pg-test-cvm.timer
```

若需撤回本轮自动化，可同样停用 `saas-staging-backup-watch@saas-pg-test-cvm.timer`，保留私有备份及状态证据，不删除业务卷。未来更新应用镜像或部署配置时，须同步核对备份环境文件、运维 compose 文件和项目身份，重新在隔离项目演练。

## 仍需推进

- 自动异机副本及保留轮换；当前自动备份在同一服务器，不能抵御整机丢失，且不会自动清理旧备份。
- 独立外部存活监测；本机断电、网络中断或巡检任务本身停用时，不能依赖自己通知。
- 备份内容包括业务数据和签名材料，需保密；服务器独立私密配置、数据库凭据及后续 HTTPS 材料还需另外安全备份。
- 当前每次巡检校验完整恢复点摘要，数据增大后应评估 I/O 耗时，调整校验频率；不要将本次小数据演练当作容量保证。
