# 后台手机号登录与防机器人接口预留

2026-11-12，从 `1ba1f39` 接续。已完成接口预留及隔离虚拟验证，**真实手机号登录保持关闭**，没有采购、配置或调用真实短信服务，没有绑定实际手机号。账号密码登录继续可用。本轮未部署云端或改动正在使用的测试工程。

## 页面和实际可用范围

登录页新增可展开的“手机号登录 · 暂未启用”区，输入和发送按钮停用，电脑、平板和手机宽度均已检查。现有密码登录及可选人机校验行为保持原样；小程序绿色基调未改动。

`app/api/admin_phone.py` 的生产依赖始终返回 `None`；不存在环境变量、配置文件或隐藏的 mock 开关可以打开它。两个预留 POST 接口 `/login/phone/request-code`、`/login/phone/verify` 在默认运行状态均不可签发验证码或会话，正常格式请求返回 503 通用停用提示。虚拟发送器仅在测试代码中，通过隔离应用显式注入；浏览器虚拟演示工具也仅保留在本机验证目录，未进入应用。

供应商接口预留 `SmsDispatcher.enqueue(phone, code, request_id)`，只有明确返回 `True` 才表示接收成功。未来实现必须按申请编号去重、限时响应、限制重试次数，并保障验证码与手机号不进入日志。没有引入实际短信 SDK、签名或模板参数。关闭的适配器直接拒绝请求。

## 已验证的保护

- 每次申请前必须完成服务端人机验证；未配置、失败、取消或异常均不发送。复用现有腾讯校验实现时强制 `required=True`，不会继承密码登录“未配置可跳过”的行为。票据摘要保存一天，重复票据即使更换随机参数也拒绝。
- 限流保存在数据库，支持多个应用进程共享。发送固定窗口：全局 200 次/小时；来源 5 次/分钟、20 次/小时；号码 1 次/分钟、5 次/小时。核验：来源 30 次/10 分钟、号码 10 次/10 分钟。达到上限返回 429 和等待时间；限流发生在调用外部人机验证之前。窗口从首次请求起算。
- 六位随机码有效期 5 分钟，单次申请最多 5 次错误核验。绑定当前浏览器的随机标识，重发会使旧码失效；延迟发送回执不能恢复已失效旧码。申请数量和限流记录有上限，满额拒绝，不挤掉仍有效的记录。
- 手机号、验证码、来源地址和人机票据在新认证表中只保存使用独立私密密钥计算的 HMAC 摘要，不保存原文。浏览器不把手机号、验证码、申请编号或会话令牌写入本地持久存储，离开页面清理输入。返回信息不回显这些内容。
- 未绑定、已停用等账号使用相同申请回复且不发送；不按真实业务表电话号码推断绑定，不自动注册账号。此处验证的是回复内容一致，未声称真实供应商环境具有恒定响应时间。
- 验证码消费、会话创建及成功审计在同一事务内完成，真实 PostgreSQL 并发只产生一个成功会话。会话入库失败全部回滚，不返回登录 Cookie。沿用既有 HttpOnly、HTTPS Secure、SameSite 和强制改密规则。
- 每次登录重新核对账号启用状态、角色、权限等级、密码状态和绑定版本。更换/解除绑定同时撤销待用验证码及目标账号已有后台会话。

## 号码绑定、更换与恢复

本轮仅保留内部绑定方法，**没有提供对外绑定入口或实际运维操作按钮**。只有正常可用且无待改密状态的超级管理员可执行，绑定目标必须是已启用并明确分配等级的管理员；一个号码仅能绑定一个管理员。解除绑定允许处理已停用账号，避免遗留绑定无法清理。每次变更检查版本，并记录不含手机号原文的操作审计。

后续启用前，需补完可审计的号码所有权确认及绑定界面：首次绑定核对已分配后台身份及号码控制权；换号先核实管理员身份、新号码及原绑定情况；旧号码遗失时经超级管理员线下核验后解除/重绑，不能靠新手机号自动恢复或提升权限。现有密码登录保留为恢复入口。不得直接调用内部方法跳过上述核验，也不在对话或 Git 中传递真实号码、验证码、密钥。

## 真实服务启用前仍需完成

1. 确认短信及人机验证供应商、签名/模板、费用与必要条件；先给用户说明方案和费用，得到采购授权后再接通。当前没有购买或计费调用。
2. 实现真实发送队列适配、按申请编号去重、超时/费用额度/失败告警和接收方不可枚举评估；确认可信代理来源地址，避免把任意转发头当作用户地址。
3. 为认证单独配置私密 HMAC 密钥与访问权限、离线保管和轮换方案，不复用备份加密私钥或其他业务凭据。换钥会影响现有号码摘要，须通过受控重绑迁移处理，不能直接换变量后宣称无影响。
4. 在独立候选环境完成号码所有权确认、绑定/换号/遗失恢复、真实人机验证、短信到达、错误及额度告警联验后，再审查生产依赖与页面启用逻辑；当前没有一键启用路径。

## 数据库与备份边界

新增迁移 `0021_admin_phone_login`：绑定表、一次性申请表、共享限流表。升级不推断或建立任何实际号码绑定；就绪检查防止新代码误启动在旧结构库上。非空表拒绝破坏性降级；空表升降级与模型一致性已分别在 SQLite、PostgreSQL 验证。

三表属于现有数据库完整导出范围，未更改自动备份、加密、异机拉取、轮换或告警任务，未访问移动硬盘或重做冷恢复。未来启用手机号能力前，须在恢复流程中补验待用验证码失效及独立认证密钥可恢复；当前预留不代表这项真实启用条件已经完成。部署仍需空闲窗口、匹配镜像/迁移的恢复点和隔离验证，不能直接对正在测试的服务升级。
