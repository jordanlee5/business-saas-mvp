# M7-22 小程序一次性权益激活接口

`POST /api/miniprogram/v1/activation/redeem` 接收 `wechat_code`、公开业务单号、手机号、车牌号和一次性激活码。仅由用户主动提交；服务端交换微信一次性 code，取得该 AppID 下的 OpenID，然后调用既有激活服务，在同一事务中核对已承接的商城业务、领取截止时间、安全因子与失败次数，并建立微信会员绑定、积分账户、批次及首条不可变流水。失败尝试和锁定状态必须提交；事务异常回滚。

成功只返回 `{ "status": "activated" }`，不返回令牌、微信身份、业务信息、手机号、车牌或积分。用过的微信 code 不再使用；后续客户端应重新调用 `wx.login`，经既有 `/auth/wechat-session` 与 `/auth/me` 创建和验证短期会话，再读取私有积分。失败的业务信息与激活码统一返回 400 与服务现有通用文案，避免枚举；微信 code 无效返回 401，配置或服务故障返回受控 5xx。响应为 `Cache-Control: no-store`，请求字段有长度上限。

截至2026-11-02，后台业务详情已支持受权限控制的首次签发，小程序已接入激活表单。激活成功后用新的登录码取得短期会话，再读取本人权益。领取、登录和身份查询的请求校验错误统一返回422及简短说明。成功、业务拒绝和请求校验响应均带 `Cache-Control: no-store`。实际微信身份交换待新账号平台联调。

本机从仓库根目录运行 `python -m tools.rehearse_member_activation` 可复验后台签发、会员领取和重复提交。工具建立临时库，调用本机 HTTP 服务的实际页面与 API，以模拟的一次性微信登录码替代外部身份交换。并发争领另在专用 PostgreSQL 测试库中验证。正式部署前仍需沿用入口请求大小和速率限制计划，每条激活凭据已有五次失败锁定。
