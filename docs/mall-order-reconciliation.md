# M6-14 已完成订单四账只读核对

`reconcile_completed_order(db, order_public_id=...)` 是内部领域查询服务，接收一个已完成且未退款的商城订单公开编号。调用方负责身份鉴权，并使用新建的、无待写入变更的数据库会话；PostgreSQL 调用方应在首次查询前设置 `REPEATABLE READ READ ONLY` 事务，以便所有核对读取同一快照。该服务没有 HTTP 入口或持久化写入。

## 核对口径

1. 对订单项、积分批次分配、预占与消费、库存预占与出库、履约审计、发货和完成审计应用已有校验；只接收 `COMPLETED` 且不含退款证据的订单。
2. 对会员积分账户及订单内每个 SKU 重算不可变流水与缓存余额；任何一处不一致都报错。
3. 搜索按订单或订单项关联的结算项，拒绝错链；每个涉及的结算批次调用已有的完整来源、成本与审计核验；逐行标明未入批次、`PENDING_CONFIRMATION` 或 `CONFIRMED`，汇总人民币成本并与订单成本合计比较。

未入批次是正常中间状态；同一订单涉及多个供应商时，部分订单项已入批次也允许。积分与人民币成本分别统计，不能互换。结果仅含内部订单项与 SKU 标识、积分和成本，不包含会员敏感信息。异常只抛错，不自动修复或改变状态。

## 验证边界

专项测试检查未入批次、部分入批次、待确认、已确认、只读 SQL，以及积分、库存、结算快照异常。独立 PostgreSQL 测试库的订单生命周期集成测试会在完成后、退款前以只读可重复读事务调用本服务。未引入新迁移，不在真实业务库写入测试订单。
