# M8-3 会员收货地址基础与接口

确认日期：2026-10-22。每位会员最多 20 条地址，删除地址簿记录，不设回收站。当前只实现后端基础及私有接口，小程序地址页面和下单接入另轮建设。

## 业务规则

- 手工填写收件人、电话、省、市、区县、详细地址。各字段必填，去首尾空白；拒绝控制字符、未知字段和超长输入。省市区暂不接行政区划服务，也不使用微信地址授权。
- 收件人上限 80 字符，省/市/区县各 80，详细地址 240。电话为 7–15 位 ASCII 数字，可带一个前导 `+`，最多 16 字符；不做短信验证。
- 空地址簿的第一条自动默认；其他新增不自动切换。设默认后原默认取消，每位会员最多一个默认。
- 删除默认且尚有其他地址时保持无默认，需会员主动选择；此时新增也不自动默认。删除全部后再次新增视为空簿首条。
- 编辑保持默认状态，20 条满额仍可编辑、设默认、删除；删除后可新增。
- 同一会员的所有写操作串行持有会员锁；SQLite 使用 BEGIN IMMEDIATE，PostgreSQL 锁会员行。数据库部分唯一索引保障默认地址唯一。

## 私有 API

前缀 `/api/miniprogram/v1`，使用既有 `Authorization: Bearer <会员会话令牌>`；会员归属只能由会话确定。

| 方法与路径 | 结果 |
| --- | --- |
| GET /addresses | 200，items/total/limit；默认在前，其余按新建顺序倒序 |
| POST /addresses | 201，完整地址对象；满额 409 |
| PUT /addresses/{address_public_id} | 200，全量替换六个手工字段，保持默认状态 |
| PUT /addresses/{address_public_id}/default | 200，显式设默认；重复操作不重复写事件 |
| DELETE /addresses/{address_public_id} | 204；再次删除 404 |

写入 JSON 仅允许 `recipient_name/phone/province/city/district/detail`。响应对象仅含这六项、`address_public_id` 和 `is_default`；不暴露会员内部 ID。随机公开 ID 为 `ADDR-` 加 32 个十六进制字符。

无效或失效会员会话返回 401；格式错误 422；不存在与其他会员的地址统一 404；数据库故障返回不含 SQL 参数的 503。所有本路由成功、鉴权错误及字段错误响应使用 `Cache-Control: no-store, private`。校验错误不回显姓名、电话或地址。客户端不得把地址或令牌放入 URL、分析埋点或控制台。

## 删除与保留

`member_addresses` 保存当前地址内容，删除时物理删除该行。`member_address_events` 只保存会员 ID、地址公开 ID、CREATE/UPDATE/SET_DEFAULT/DELETE、发生时间；与业务写操作同事务提交。事件不保存地址副本、不关联可恢复的旧内容，也不提供回收站或还原接口。

物理删除是在线地址簿层面的删除，不宣称立即擦除 SQLite 空闲页、WAL、历史备份或未来独立订单快照。备份按既有备份管理处理，禁止把数据库副本提交 Git 或上传聊天；本轮不新增历史地址副本。订单接入时须独立保存下单时收货快照，本轮不改已有订单模型或历史数据。

## 迁移和逐阶段验收

迁移：`0011_supplier_settlement_foundation` → `0012_member_addresses`，新增两张空表和约束，不填充虚拟会员、商品、订单或地址。代码启动检查要求新版本与表结构就绪。

固定 11 阶段继续沿用。Stage3A 先只读真实 SQLite，使用 SQLite backup API 生成独立副本，核对既有表结构及每表数据指纹，演练升级→空表降级→再升级，复核真实库未变。命令 `python -m app.member_address_migration_check --source saas_mvp.db --output <新的本地目录>` 只能操作新副本，没有真实库升级模式。

用户已确认：副本演练截图通过后，再单独确认真实库备份和升级（Stage3B）。不得把演练 PASS 当作真实库已升级。未完成该关口不能启动新版本应用；升级时先停服务、备份并验证，之后核对版本、空表、既有业务数据指纹。地址或事件表非空时禁止自动降级；离线降级也拒绝生成删除脚本。

必要验收：20 条边界及并发超限；首条默认、显式切换、删默认无替补、删空再新增；跨会员隔离；失效/篡改/停用会员；错误响应无私密输入；失败全部回滚；SQLite 及 PostgreSQL 默认唯一；副本迁移保留既有数据；既有会员激活、积分与后台回归；运行态无令牌地址接口 401。

专项自动化使用隔离测试会员，不代表正式微信会员正向。PostgreSQL 新增同一组 15 项 HTTP/并发验收，Stage6 与原有激活、积分流水两项合计 17 项，测试前后必须为空白专用测试库。其余历史 PostgreSQL 测试组不因此视为通过。

## 后续窗口与 DEFERRED

M8-3 后端验收后、地址页面开发接入前，安排正式小程序 AppID 的注册与配置窗口：先确认主体及用途，再按当时微信官方要求逐项完成注册、开发者权限、服务配置和隐私配置。密钥只在本地配置，不粘贴聊天。条件具备后依次补验微信身份绑定、真实会员登录及积分、地址接口/页面、下单购物全流程。

真实公开商品操作和详情重读仍因公开商品数量为零 DEFERRED；正式平台隐私、真实会员、合法 HTTPS 域名与真机正向仍 DEFERRED。本轮新增真实会员地址正向也待上述条件具备后补验。自动化测试和推送成功均不能将这些项目改为 PASS。
