# 数据库迁移目录

本目录由 Alembic 管理。迁移版本统一放入 `versions/`，并必须同时提供可审阅的 `upgrade()` 与 `downgrade()`。

`0001_current_schema_baseline` 固化稳定基线 `ee34b97` 的 10 张既有业务表，不包含商城字段或数据变更。空数据库可通过它重建当前结构；已有数据库必须先运行 `python -m app.migration_baseline` 做只读结构检查，完成备份与审阅后才允许使用 `--apply` 写入版本标记。`downgrade base` 只用于无业务数据的临时测试库，严禁对已有业务数据库执行。

`0002_mall_core_foundation` 新增上传批次与业务记录的商城渠道字段，并建立会员、微信绑定、积分账户、积分批次和积分流水五张核心表。历史批次与业务记录全部回填为 `CASH_REBATE`。真实 SQLite 数据库从 0001 升级前，必须停止应用并运行 `python -m app.migration_upgrade_rehearsal`；只有副本升级、历史原字段数据指纹、重复升级与结构漂移检查全部通过后，才可另行批准真实升级。

`0003_member_activation_security` 新增商城业务激活凭据表，激活码仅保存带随机盐的版本化摘要，并由数据库约束安全因子、生命周期、错误次数、重签版本和有效期。升级演练同时支持从 `0001_current_schema_baseline` 或 `0002_mall_core_foundation` 到当前 head；源库与升级前快照不会被演练修改。

`0004_catalog_foundation` 新增商品分类、供应商、商品和 SKU 四张空表，固化商品生命周期、积分售价、人民币成本、供应商归属、排序和低库存阈值的数据库约束。升级演练继续支持 `0001`、`0002`，并新增真实 `0003_member_activation_security` 源库的结构预检；本迁移不改写既有业务、会员、积分或现金返现数据。

`0005_product_media` 新增商品主图、轮播图和详情图表，保存独立文件路径、用途、排序、启用状态、替代文字和上传管理员。条件唯一索引保证每个商品最多一张主图。升级演练新增真实 `0004_catalog_foundation` 源库结构预检；迁移只新增空表，不改写现有目录或历史业务数据。

`0006_inventory_foundation` 新增 SKU 库存余额和不可变流水两张空表，保存现存/预占数量、余额版本、变动前后数量、原因、操作者和幂等键。升级演练新增真实 `0005_product_media` 源库结构预检；迁移不为既有 SKU 写入余额，也不改写目录、积分或现金返现数据。

`0007_order_foundation` 新增订单主表、订单项目录与价格成本快照表、订单积分批次分配表。升级演练新增真实 `0006_inventory_foundation` 源库结构预检；迁移只创建空表，不预占或消费积分、不变更库存，也不写入测试数据。

`0008_order_reservation` 为订单增加唯一幂等键，并扩展库存流水，使现存量与预占量共享连续版本和不可变前后值；订单预占流水记录会员与订单来源。升级演练支持审计后的 `0007_order_foundation` 源库，迁移本身不创建订单或预占任何真实库存、积分。

`0009_order_shipping_completion` 为订单增加物流公司、运单号、发货时间和完成时间，并以完整性、状态、唯一性约束防止无物流证据的已发货/已完成订单。已审计的 `0008_order_reservation` SQLite 源库可先通过升级副本演练；如果源库已存在缺少证据的 `SHIPPED` 或 `COMPLETED` 数据，升级会失败关闭。存在任何发货或完成证据时，降级到 `0008` 也会被拒绝。

`0010_order_refund_recovery` 为订单增加退款原因和退款时间，并扩展生命周期约束以保证 `REFUNDED` 必须同时具备完成与退款事实。已审计的 `0009_order_shipping_completion` SQLite 源库可先通过升级副本演练；如果源库已有无法证明积分、库存恢复的 `REFUNDED` 数据，升级会失败关闭。存在退款状态或证据时，降级到 `0009` 也会被拒绝。

已有 SQLite 数据库在考虑写入版本标记前，还必须停止应用并运行 `python -m app.migration_rehearsal`。演练只修改单独副本，并保留原始快照；演练通过不等于获准修改真实数据库。历史兼容画像只接受已审计的等价类型、默认值、三个索引和三个外键差异，并要求审核人、凭证上传批次、布尔值与费率模式完整性检查全部通过。

应用启动不再执行 `Base.metadata.create_all()`。当前代码只接受真实处于 `0010_order_refund_recovery` 且 26 张必需表及关键字段完整的数据库，版本落后或虚假 stamp 都会失败关闭。
